# llm-provider Specification

## Purpose

Изолирует доступ к LLM за единым контрактом, позволяя менять поставщика (LM Studio, Ollama, vLLM, OpenAI и др.) через конфигурацию без правок вызывающего кода, и обеспечивает предсказуемое поведение при недоступности провайдера.

## Requirements

### Requirement: Единый контракт вызова LLM
Доступ к LLM SHALL предоставляться через единый контракт, принимающий список сообщений диалога, опциональный набор описаний инструментов и опциональное указание формата ответа (response_format), и возвращающий ход ассистента, состоящий из финального текста и/или вызовов инструментов. Ход ассистента MAY дополнительно нести метаданные использования поставщика (usage): входные, выходные, кэшированные и reasoning-токены, извлекаемые из ответа поставщика при их наличии; поля, которых ответ не содержит, SHALL оставаться null, а не отбрасываться. Присутствие или отсутствие usage MUST NOT влиять на разбор текста, вызовов инструментов и finish_reason. Указание формата ответа SHALL пробрасываться поставщику, когда тот его поддерживает; для поставщика без поддержки контракт SHALL отправлять запрос без указания формата, не считая это ошибкой. Вызывающий код MUST NOT знать о конкретном поставщике, формате его API или сетевых деталях. Сообщения диалога SHALL поддерживать роли `system`, `user`, `assistant` и `tool`; сообщения `assistant` MAY нести вызовы инструментов, сообщения `tool` — результат конкретного вызова по его идентификатору. Вызов без инструментов SHALL оставаться семантически эквивалентным прежнему одноходовому вызову.

#### Scenario: Вызов с одним пользовательским сообщением
- **WHEN** вызывающий код передаёт список из одного user-сообщения без описаний инструментов
- **THEN** контракт возвращает ход ассистента с финальным текстом и пустым списком вызовов инструментов

#### Scenario: Вызов с инструментами
- **WHEN** переданы описания инструментов и модель решает воспользоваться инструментом
- **THEN** контракт возвращает ход ассистента с пустым текстом и непустым списком вызовов инструментов

#### Scenario: Вызов с указанием формата ответа
- **WHEN** вызывающий код передаёт указание формата ответа (например JSON-схему), а поставщик его поддерживает
- **THEN** запрос к поставщику содержит соответствующее поле формата ответа

#### Scenario: Изоляция поставщика
- **WHEN** меняется поставщик LLM (LM Studio → Ollama → OpenAI)
- **THEN** вызывающий код не изменяется

#### Scenario: Ответ содержит usage
- **WHEN** поставщик вернул usage с числом входных и выходных токенов
- **THEN** ход ассистента несёт эти значения, а отсутствующие в ответе составляющие (cached, reasoning) равны null

#### Scenario: Ответ без usage
- **WHEN** поставщик не вернул поле usage
- **THEN** ход ассистента несёт null-метаданные использования и разбирается без ошибки

### Requirement: Поддержка OpenAI-совместимых поставщиков
Система SHALL предоставлять реализацию контракта для OpenAI-совместимых эндпоинтов (`/v1/chat/completions`), параметризуемую базовым URL, именем модели и опциональным API-ключом. Реализация SHALL покрывать LM Studio, Ollama (через `/v1`), vLLM и OpenAI без изменения кода, включая передачу описаний инструментов и полный tool-call round-trip: проброс `tools` в запрос, разбор `tool_calls` из ответа (включая аргументы как JSON-строку) и сериализацию истории с ролями `assistant` (с `tool_calls`) и `tool` (с `tool_call_id`) в последующих запросах.

#### Scenario: Локальный LM Studio без API-ключа
- **WHEN** конфигурация указывает `LLM_BASE_URL=http://localhost:1234/v1` и модель `openai/gpt-oss-20b` без API-ключа
- **THEN** запросы идут к локальному LM Studio без заголовка авторизации

#### Scenario: Облачный OpenAI-совместимый поставщик с ключом
- **WHEN** конфигурация указывает облачный `LLM_BASE_URL` и `LLM_API_KEY`
- **THEN** запросы идут к облачному поставщику с заголовком `Authorization: Bearer <key>`

#### Scenario: Round-trip вызова инструмента
- **WHEN** модель отвечает вызовом инструмента (`finish_reason=tool_calls`, аргументы как JSON-строка)
- **THEN** реализация возвращает ход с разобранными вызовами инструментов, а при передаче в следующий вызов истории с assistant-сообщением (с `tool_calls`) и tool-сообщением (с `tool_call_id`) поставщик принимает запрос и возвращает финальный ответ

### Requirement: Предпочтение endpoint'а в строке модели
Строка модели из конфигурации SHALL передаваться поставщику без искажений,
включая форму `<model>@<key>=<value>&<key>=<value>` — параметры роутинга
агрегатора (провайдер, fallback) после `@` являются частью имени модели и
MUST NOT вырезаться, нормализоваться или валидироваться клиентом. Это
позволяет фиксировать конкретный endpoint агрегатора (например, дешёвый
тир) чистой конфигурацией, без расширения контракта вызова.

#### Scenario: Пин endpoint'а передаётся насквозь
- **WHEN** конфигурация задаёт модель вида `openai/gpt-5.6-luna@provider=openai/flex&allow_fallbacks=false`
- **THEN** запрос к поставщику содержит строку модели как есть, ответ
  разбирается штатно, вызовы обслуживаются указанным endpoint'ом

#### Scenario: Имя модели без параметров роутинга
- **WHEN** конфигурация задаёт обычное имя модели без `@`
- **THEN** поведение не отличается от прежнего (локальный LM Studio и др.)

### Requirement: Выбор поставщика по конфигурации
Система SHALL выбирать реализацию контракта по значению `LLM_PROVIDER` из окружения. Неизвестное значение SHALL вызывать явную ошибку конфигурации при старте, а не молчаливое падение во время работы.

#### Scenario: Поставщик по умолчанию
- **WHEN** `LLM_PROVIDER` не задан
- **THEN** используется OpenAI-совместимая реализация

#### Scenario: Неизвестный поставщик
- **WHEN** `LLM_PROVIDER` содержит значение без соответствующей реализации
- **THEN** бот не стартует и выводит понятную ошибку о неизвестном поставщике

### Requirement: Предсказуемое поведение при недоступности LLM
Временные сбои вызова LLM — обрыв соединения или ответа, таймаут, HTTP 5xx,
а также HTTP 404 при жёстком пине endpoint'а — SHALL ретраиться клиентом
автоматически: суммарно до 3 попыток с паузами между повторами. Исчерпание
попыток, как и любые другие ошибки, SHALL возбуждать единое исключение
недоступности LLM, которое вызывающий код может перехватить для показа
пользовательского сообщения. Постоянные ошибки запроса (HTTP 4xx, кроме
404) SHALL завершаться исключением немедленно, без повторов. Контракт MUST
NOT возвращать пустой или молчаливый результат при ошибке.

#### Scenario: Обрыв ответа и успешный повтор
- **WHEN** поставщик оборвал ответ (ошибка передачи), а повторная попытка
  завершилась успешно
- **THEN** вызывающий код получает штатный ход ассистента, без исключения

#### Scenario: Исчерпание повторов
- **WHEN** все попытки вызова исчерпаны из-за повторяющихся сетевых сбоев
- **THEN** контракт возбуждает исключение недоступности LLM

#### Scenario: Постоянная ошибка без повторов
- **WHEN** поставщик ответил 401/402/400
- **THEN** исключение недоступности LLM возбуждается сразу, без пауз и повторов

#### Scenario: Сервер не запущен
- **WHEN** LLM-сервер не принимает соединения и не поднимается за окно повторов
- **THEN** контракт возбуждает исключение недоступности LLM

#### Scenario: Модель не загружена
- **WHEN** сервер отвечает, но модель не загружена (ошибка 4xx/5xx)
- **THEN** контракт возбуждает исключение недоступности LLM

#### Scenario: Таймаут ответа
- **WHEN** LLM не отвечает в течение настроенного таймаута на каждой из попыток
- **THEN** контракт возбуждает исключение недоступности LLM, а не зависает бесконечно

### Requirement: Конфигурация только через окружение
Все параметры LLM (`LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`) SHALL читаться из переменных окружения / `.env` и MUST NOT захардкоживаться в исходном коде.

#### Scenario: Значения по умолчанию
- **WHEN** `LLM_BASE_URL` и `LLM_MODEL` не заданы
- **THEN** используются значения по умолчанию для локального LM Studio (`http://localhost:1234/v1`) и модели `openai/gpt-oss-20b`

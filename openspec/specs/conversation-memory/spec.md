# conversation-memory Specification

## Purpose

Персистентное хранилище переписки бота: организует диалог в сессии, сохраняет сообщения пользователя и финальные ответы ассистента на VM-локальном диске, восстанавливает контекст открытой сессии после рестарта и даёт агенту инструмент поиска по прошлым беседам.

## Requirements

### Requirement: Запись переписки в персистентное хранилище
Все сообщения пользователя и финальные ответы ассистента SHALL записываться в персистентное хранилище в момент обработки сообщения. Промежуточный инструментальный транскрипт (ходы ассистента с вызовами инструментов и tool-сообщения с их результатами) MUST NOT записываться в хранилище. Reasoning-поле модели в хранилище не попадает.

#### Scenario: Сообщение и ответ сохранены
- **WHEN** пользователь отправляет сообщение и получает финальный ответ ассистента
- **THEN** оба сообщения доступны в хранилище после завершения обработки

#### Scenario: Инструментальный транскрипт не сохраняется
- **WHEN** обработка сообщения включала вызовы инструментов и их результаты
- **THEN** в хранилище записываются только исходное сообщение пользователя и финальный ответ, без промежуточных инструментальных ходов

### Requirement: Сессии переписки
Переписка чата SHALL быть организована в сессии: в каждый момент у чата не более одной открытой сессии; новые сообщения пишутся в открытую сессию. Команда `/new` закрывает открытую сессию (с фиксацией времени завершения) так, что последующие сообщения открывают новую. Завершённые сессии сохраняются в хранилище.

#### Scenario: Сообщения накапливаются в одной сессии
- **WHEN** пользователь отправляет несколько сообщений без команды `/new`
- **THEN** все они и ответы на них относятся к одной открытой сессии

#### Scenario: /new разделяет сессии
- **WHEN** пользователь отправляет `/new`, а затем новое сообщение
- **THEN** новое сообщение открывает новую сессию, а прежняя остаётся в хранилище завершённой

### Requirement: Восстановление контекста после рестарта
Контекст открытой сессии SHALL восстанавливаться из хранилища при обработке сообщения: перезапуск процесса бота MUST NOT терять переписку. Восстановленный контекст содержит сообщения пользователя и финальные ответы ассистента открытой сессии; инструментальный транскрипт, предшествовавший рестарту, не восстанавливается.

#### Scenario: Рестарт не стирает диалог
- **WHEN** бот перезапущен между сообщениями пользователя в пределах одной сессии
- **THEN** запрос к LLM по следующему сообщению содержит предшествующую переписку сессии, восстановленную из хранилища

#### Scenario: Контекст после рестарта не содержит инструментальных ходов
- **WHEN** до рестарта обработка сообщения включала вызовы инструментов
- **THEN** восстановленный контекст содержит исходное сообщение и финальный ответ той обработки, но не инструментальный транскрипт

### Requirement: Изоляция чатов
Переписка одного чата MUST NOT быть видима из другого чата ни при восстановлении контекста, ни через поиск по прошлым беседам.

#### Scenario: Чаты не видят переписку друг друга
- **WHEN** два разных чата ведут диалоги с ботом
- **THEN** контекст и результаты поиска в каждом чате содержат только его собственную переписку

### Requirement: Инструмент поиска по прошлым беседам
Модель SHALL иметь доступный инструмент `search_history`, принимающий текстовый запрос и возвращающий выдержки сообщений завершённых сессий текущего чата, релевантные запросу, с указанием принадлежности к сессии и времени. Инструмент SHALL быть строго читающим: он MUST NOT изменять историю или состояние сессий. Суммарный объём результата SHALL быть ограничен, чтобы не разбухал контекст.

#### Scenario: Поиск находит прошлую беседу
- **WHEN** модель вызывает `search_history` с запросом, соответствующим содержанию завершённой сессии
- **THEN** модель получает выдержки сообщений этой сессии с признаком сессии и временем

#### Scenario: Ничего не найдено
- **WHEN** модель вызывает `search_history` с запросом, которому ничего не соответствует
- **THEN** модель получает явный ответ об отсутствии результатов

#### Scenario: Результат ограничен по объёму
- **WHEN** запросу соответствуют многие сообщения
- **THEN** инструмент возвращает ограниченный объём выдержек, а не всю переписку

### Requirement: Размещение и живучесть хранилища
Хранилище SHALL представлять собой файл(ы) на VM-локальном диске сандбокса и MUST NOT размещаться в workspace-маунте. Хранилище SHALL переживать рестарты процесса бота и остановку/возобновление сандбокса; полный сброс сандбокса стирает хранилище — это осознанное ограничение, не сбой.

#### Scenario: Пауза и возобновление сандбокса
- **WHEN** сандбокс остановлен командой остановки и затем возобновлён
- **THEN** переписка открытой сессии доступна и контекст восстанавливается

#### Scenario: Полный сброс стирает память
- **WHEN** выполнен полный сброс сандбокса
- **THEN** хранилище переписки отсутствует, бот начинает с пустой историей; это не считается ошибкой

## Why

Дефолты проекта описывают стек, которым им никто не пользуется. В коде и в спеках по умолчанию стоит локальный LM Studio (`http://localhost:1234/v1`, `openai/gpt-oss-20b`), а рабочая конфигурация — routerai с `openai/gpt-5.6-luna` для финального ответа и `baai/bge-m3` для эмбеддингов. `sbx-start.sh` предлагает LM Studio-дефолты, поэтому Enter×3 в ежедневном запуске даёт стек, на котором RAG не работает: `bge-m3` локальный сервер не обслуживает.

Отдельная дыра — модель эмбеддингов вообще не участвует в интерактивном выборе при запуске, хотя именно она определяет совместимость с существующим индексом `rag.db`.

## What Changes

- Дефолтный base URL всех LLM-вызовов (чат и эмбеддинги) — `https://routerai.ru/api/v1` вместо локального LM Studio. **BREAKING** для запуска без явной конфигурации: раньше «из коробки» подразумевался локальный сервер, теперь облачный, а значит нужен ключ.
- Дефолтная модель финального ответа — `openai/gpt-5.6-luna` вместо `openai/gpt-oss-20b`.
- `sbx-start.sh` спрашивает **четыре** параметра вместо трёх: общий `LLM_BASE_URL`, `LLM_MODEL`, `EMBEDDING_MODEL` и общий `LLM_API_KEY`.
- Дефолт ключа в промпте берётся из workspace-`.env`, а не пустая строка: при облачном дефолтном URL пустой ключ дал бы нерабочий Enter-сценарий. Значение по-прежнему не отображается — только признак «задан / не задан».
- Наследование endpoint'а и ключа эмбеддингов от chat-конфигурации **сохраняется** и становится нормативным: один URL и один ключ на всё, а `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY` остаются override'ом для случая, когда эмбеддинги берутся у другого поставщика.
- Модель эмбеддингов остаётся независимой от chat-модели со своим дефолтом `baai/bge-m3`.

## Capabilities

### New Capabilities

(нет — новых возможностей не добавляется)

### Modified Capabilities

- `llm-provider`: значения по умолчанию для base URL и модели становятся облачными (routerai + `openai/gpt-5.6-luna`).
- `sbx-hosting`: интерактивный выбор при запуске расширяется до четырёх параметров, дефолты меняются, дефолт ключа берётся из `.env`.
- `embedding-provider`: наследование chat-endpoint'а и chat-ключа по умолчанию фиксируется требованием (сейчас это поведение живёт только в коде).

## Impact

- `src/dev_helper_bot/config.py` — `DEFAULT_BASE_URL`, `DEFAULT_MODEL`.
- `scripts/sbx-start.sh` — четвёртый промпт, новые дефолты, чтение дефолта ключа из `.env`, проброс `EMBEDDING_MODEL` через `-e`.
- `tests/unit/test_config.py` — тесты, прибивающие дефолты гвоздями (строки с `http://localhost:1234/v1` и `openai/gpt-oss-20b`).
- `.env.example`, `README.md` (таблица переменных, раздел ежедневного запуска, раздел «Эмбеддинги»), `AGENTS.md` (устаревшая gotcha про `sbx-start.sh`).
- `scripts/sbx-setup.sh` не меняется: разовая network policy на `localhost:1234` нужна локальному сценарию, который остаётся доступным вводом с клавиатуры.
- Существующий `rag.db` пересобирать не нужно: индекс построен через routerai и `bge-m3`, то есть ровно новыми дефолтами.

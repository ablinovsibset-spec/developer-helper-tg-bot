## Context

Мотивация — proposal.md («Why»). Здесь важны четыре факта о текущем коде.

Дефолты живут в **двух** местах: `config.py` (`DEFAULT_BASE_URL`, `DEFAULT_MODEL`, `DEFAULT_EMBEDDING_MODEL`) и `scripts/sbx-start.sh` (`DEFAULT_LLM_*`, показываемые в промптах). Скрипт всегда передаёт свои значения через `-e`, поэтому в сандбоксе видны его дефолты, а не пакетные; пакетные работают при запуске на хосте.

`make_embeddings()` разрешает endpoint и ключ каскадом `EMBEDDING_* → LLM_* → дефолт`, а модель — независимо (`EMBEDDING_MODEL → baai/bge-m3`). Этот каскад сохраняется.

`scripts/sbx-start.sh` сегодня `.env` не читает вовсе: токен и остальное подхватывает `load_dotenv()` уже внутри VM. Для дефолта ключа в промпте скрипту придётся впервые заглянуть в `.env` на хосте.

Архивный дизайн `2026-09-10-interactive-llm-on-sbx-start` содержит два решения, которые этот change отменяет: D2 («дефолты фиксированные LM Studio, не из `.env`») и часть D3 («пустой ключ передаём явно, чтобы облачный ключ из `.env` не протёк в локальный сеанс»).

## Goals / Non-Goals

**Goals:**
- Дефолты, описывающие реально используемый стек, — чтобы Enter в ежедневном запуске давал работающий бот вместе с RAG.
- Модель эмбеддингов — такой же явный выбор при запуске, как модель финального ответа.
- Сохранить локальный сценарий рабочим: он перестаёт быть дефолтом, но не становится неудобным.

**Non-Goals:**
- Разрыв наследования endpoint'а и ключа эмбеддингов от chat-конфигурации: один URL и один ключ на всё — это и есть желаемое поведение.
- Fail-fast при отсутствии ключа. После смены дефолтов чат и эмбеддинги равно зависят от ключа и равно падают без него; отдельная проверка для эмбеддингов больше не оправдана.
- Пресеты-меню («1) LM Studio 2) routerai») вместо свободного ввода.
- Пин тира routerai (`@provider=…&allow_fallbacks=false`) в дефолтной модели.
- Изменение виртуального прайса телеметрии (см. D6).
- Изменения `scripts/sbx-setup.sh`: разовая policy на `localhost:1234` нужна локальному сценарию и вреда не несёт.

## Decisions

### D1: Наследование эмбеддингов сохраняется, дефолт лечит проблему сам

Исходная опасность была не в каскаде, а в том, что дефолт чата уводил эмбеддинги на локальный LM Studio, где `bge-m3` нет. Когда дефолтный URL стабильно облачный, каскад из ловушки превращается в удобство: один адрес и один ключ на диалог и индексацию.

Альтернатива «дать эмбеддингам свои константы и не смотреть на `LLM_*`» отвергнута: она заводит вторую копию тех же двух значений и обязывает оператора держать `EMBEDDING_API_KEY` в `.env` ради сценария, которого у него нет.

Чтобы поведение перестало быть неявным, наследование становится нормативным в `embedding-provider` — раньше оно жило только в коде и комментарии.

### D2: Дефолты дублируются в `config.py` и `sbx-start.sh`

Скрипт продолжает нести свои bash-константы, а не спрашивать их у пакета. Вытащить значения из установленного пакета (`python -c "from dev_helper_bot.config import DEFAULT_MODEL; …"`) можно, но это привязывает промпты хоста к состоянию venv на хосте, который для сандбокс-сценария вообще не нужен.

Trade-off: два места для одной правки. Смягчается тем, что оба значения перечислены в README-таблице, и задача правит их одним заходом.

### D3: Дефолт ключа читается из `.env` точечно, не через `source`

Скрипт извлекает только строку `LLM_API_KEY=` (например `sed -n`), а не подгружает файл целиком. `source .env` затянул бы в окружение скрипта `TELEGRAM_BOT_TOKEN` и позволил бы файлу исполнить произвольный код при каждом запуске.

Приоритет для ключа: экспортированное окружение вызывающего shell → значение из `.env` → пусто. Для URL и модели — экспортированное окружение → константа скрипта (как сегодня).

Граница доверия не двигается: `.env` и так доступен процессу бота, а недоступен он командам агента внутри контейнера-жильца. Скрипт исполняется на хосте, то есть по ту же сторону границы.

### D4: Явный сброс ключа — ввод одного дефиса

Раз дефолт ключа больше не пустой, нужен способ выбрать пустое значение, отличимый от Enter. Ввод `-` трактуется как «ключ пустой». Так сохраняется смысл отменённой части архивного D3: сеанс на локальном сервере можно запустить, не отправляя туда облачный ключ.

Альтернатива «спрашивать отдельным да/нет вопросом» отвергнута: это пятый промпт ради редкого случая.

### D5: В `-e` уходит `EMBEDDING_MODEL`, но не `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY`

Модель эмбеддингов выбирается оператором, поэтому её значение обязано победить `.env`. Endpoint и ключ эмбеддингов, напротив, скрипт передавать не должен: они существуют ровно для сценария «отдельный поставщик эмбеддингов» и живут в `.env`. Если бы скрипт их затенял, этот сценарий стал бы недостижимым из сандбокса.

### D6: Виртуальный прайс телеметрии не меняется

`OBS_PRICE_INPUT_PER_M` / `OBS_PRICE_OUTPUT_PER_M` остаются 0.11 / 0.60. Это учётная величина для сопоставимости экспериментов «до/после», а не прайс-лист текущей модели; привязка к дефолтной модели была бы ложной точностью. Комментарий в коде и README формулируются так, чтобы не выглядеть утверждением о цене `openai/gpt-5.6-luna`.

## Risks / Trade-offs

- [Enter×4 теперь тратит деньги, тогда как раньше дефолт был бесплатным локальным стеком] → выбранный URL виден в промпте и печатается в `say` перед запуском; README открывает раздел запуска этим фактом.
- [Оператор без ключа в `.env` получает молчаливо нерабочий бот: чат отвечает ошибкой на первое сообщение] → это существующее поведение проекта и одинаково для чата и эмбеддингов; отдельный fail-fast сознательно вне scope (Non-Goals).
- [Дублирование дефолтов между `config.py` и `sbx-start.sh` разъедется] → README-таблица как единственное человекочитаемое место истины; правка обоих файлов — одна задача.
- [Ключ из `.env` попадает в локальный сеанс, если оператор ввёл локальный URL и нажал Enter на ключе] → документированный сброс через `-` (D4); локальные серверы заголовок авторизации игнорируют, поэтому ущерб в худшем случае нулевой.
- [Спека `llm-provider` теперь называет конкретного вендора в дефолте] → значение перекрывается окружением, а требование явно говорит, что это дефолт, а не хардкод.

## Migration Plan

1. Обновить код, скрипт, тесты и документацию; прогнать `pytest`.
2. Перезапустить бот: `scripts/sbx-start.sh`, Enter×4. Существующий `rag.db` пересобирать не нужно — он построен теми же routerai + `bge-m3`.
3. `.env` править не обязательно: он уже содержит routerai, `openai/gpt-5.6-luna` и ключ.
4. Откат: вернуть прежние значения `DEFAULT_BASE_URL` / `DEFAULT_MODEL` и три промпта в `sbx-start.sh`.

## Context

Репозиторий пустой, кроме `explore/homework.md` (см. proposal.md — Why). Бот — это «клей» между Telegram и локальной LLM, и единственная нетривиальная часть — изоляция доступа к LLM, чтобы поставщика можно было сменить без правок бота. Горизонт 3 месяца означает, что структура должна пережить добавление памяти, команд и переключение моделей.

## Goals / Non-Goals

**Goals:**
- Узкий шов `LLMClient` между ботом и LLM; `bot.py` не знает про конкретного поставщика.
- Одна реализация (`OpenAICompatibleClient`) покрывает большинство поставщиков через конфиг.
- Асинхронность везде (aiogram + aiohttp), чтобы бот не блокировался на генерации.
- Запуск за `python bot.py` после поднятия LM Studio сервера.

**Non-Goals:**
- Память диалога между сообщениями (явно вне scope задания).
- Стриминг ответа с редактированием сообщения (one-shot ответ).
- Webhooks (long-polling достаточен для ноутбука).
- Поддержка не-OpenAI-совместимых поставщиков (Anthropic, родной Ollama `/api/generate`) — закладывается место, но реализации не пишутся.
- Тесты на этом этапе (домашка; добавим при необходимости позже).

## Decisions

### Решение 1: aiogram 3.x вместо telebot
Асинк aiogram позволяет обслуживать несколько пользователей параллельно, пока LLM генерит ответ (2–5 сек для 3B-модели). telebot синхронный и блокировался бы на каждом запросе. Альтернатива — telebot — проще, но блокирующая модель конфликтует с 3-месячным ростом. aiogram 3.x также вероятнее то, что курс будет использовать позже.

### Решение 2: Шов LLMClient с контрактом `complete(messages) -> str`
Интерфейс принимает список сообщений, а не один текст. Это совпадает с OpenAI API нативно (без трансляций) и переживает добавление памяти диалога без изменения интерфейса — one-shot вызов просто передаёт `[{role:user, content:text}]`. Альтернатива `complete(text) -> str` проще сейчас, но потребует менять интерфейс и все реализации при добавлении памяти. Цена варианта B — одна строка-обёртка в `bot.py` сейчас.

### Решение 3: Один класс OpenAICompatibleClient для большинства поставщиков
LM Studio, Ollama (`/v1`), vLLM, OpenAI, Groq, Together держат один эндпоинт `/v1/chat/completions`. Различаются только `base_url`, `model` и опциональный `api_key`. Поэтому один параметризуемый класс покрывает ~90% случаев; смена поставщика = правка `.env`. Не-OpenAI-совместимые поставщики — отдельные файлы, добавляются только при необходимости. Альтернатива — один класс на поставщика — дублировала бы идентичный HTTP-код.

### Решение 4: aiohttp для вызовов LLM
aiohttp подтягивается транзитивно через aiogram, поэтому лишних зависимостей нет, и он асинхронный — не блокирует event loop aiogram. Альтернатива — `requests` — синхронная и требовала бы `asyncio.to_thread`, либо `httpx` — лишняя зависимость при уже имеющемся aiohttp.

### Решение 5: Фабрика `make_llm()` по `LLM_PROVIDER`
`config.py` читает env и возвращает реализацию `LLMClient`. Неизвестное значение — явная ошибка при старте, не молчаливое падение в рантайме. Значения по умолчанию настроены на локальный LM Studio.

### Решение 6: Структура модулей
```
developer-helper-tg-bot/
├── bot.py              # aiogram: handler, chunking, graceful fallback
├── llm/
│   ├── __init__.py     # экспорт make_llm()
│   ├── base.py         # LLMClient (Protocol) + LLMUnavailable
│   └── openai_compat.py  # OpenAICompatibleClient
├── config.py           # загрузка .env + make_llm()
├── .env.example
└── requirements.txt
```
`bot.py` зависит только от `LLMClient` из `llm.base` — не от конкретной реализации. Это и есть глубокий модуль: узкий интерфейс, широкая реализация.

## Risks / Trade-offs

- [LM Studio сервер должен быть поднят вручную до старта бота] → бот при старте не валидирует доступность LLM; вместо этого первая ошибка запроса перехватывается и пользователю показывается человекочитаемое сообщение, поллинг продолжается. Дополнительно — понятная ошибка в лог при недоступности.
- [Отклонение от рекомендуемого стека (LM Studio вместо Ollama/vLLM)] → технически эквивалентно (локальная модель, OpenAI-совместимый API); если курс оценивает конкретно Ollama, смена поставщика = правка `.env`, код не меняется.
- [Llama-3.2-3B может отвечать дольше 1–2 сек] → таймаут в `OpenAICompatibleClient` настраивается (по умолчанию 60 сек); при истечении — исключение недоступности, пользователь получает сообщение об ошибке.
- [Ответ длиннее 4096 символов] → чанкинг по 4096 с последовательной отправкой; риск разрыва в середине слова/кода приемлем для домашки.
- [Не-OpenAI-совместимый поставщик понадобится позже] → структура `llm/` позволяет добавить файл без правок `bot.py`; контракт `complete(messages)` это поддерживает.

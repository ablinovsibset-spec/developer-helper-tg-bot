## Context

Скиллы — данные, не код: новая функциональность выражается текстовой инструкцией, код
бота и тесты не меняются (см. proposal.md). Ключевые ограничения среды, в которой
работает скилл:

- вывод `exec` обрезается до 3000 символов (`OUTPUT_LIMIT` в `src/dev_helper_bot/tools.py`);
- бот отправляет ответы с `parse_mode=HTML` (`main.py`, `DefaultBotProperties`);
- на хосте есть `curl` и `python3` (бот сам — Python-приложение);
- утренняя рутина уже опирается на паттерн «рутина (Тип B) ссылается на API-скилл (Тип A)».

Источник проверен эмпирически (2026-08-28): `https://habr.com/ru/rss/articles/top?fl=ru`
отвечает 200 (~99 KB, 40 айтемов, отсортированы по рейтингу, даты охватывают ~неделю);
фильтр по `pubDate` за 24 ч оставляет 2–6 статей; компактный вывод — ~0,4 КБ.

## Goals / Non-Goals

**Goals:**

- Дайджест «топ Habr за 24 часа, до 10 статей» в утренней сводке, с кликабельными
  ссылками — поведение согласно дельте спеки `skills`.
- Уложиться в лимит вывода `exec` с многократным запасом.
- Следовать паттерну проекта: новый скилл Типа A + правка рутины Типа B.

**Non-Goals:**

- Персональная лента Habr (требует токен из настроек аккаунта, анонимный
  `/ru/rss/feed/` даёт 302).
- Покрытие *всех* новых статей за сутки (в сутках ~200; RSS отдаёт 40 ≈ 4,5 часа) —
  осознанно берём кураторский топ.
- Пагинация, фильтры по хабам, рейтинги, счётчики — не нужны для утреннего дайджеста.

## Decisions

### 1. Источник: RSS `articles/top` + фильтр по `pubDate` на стороне клиента

Альтернативы отклонены по результатам проверки:

| Вариант | Верди́кт |
|---|---|
| HTML `https://habr.com/ru/feed/` | 336 KB, анонимно — дефолтные хабы, убьётся об лимит 3000 |
| `/ru/rss/feed/` (персональная) | 302 без токена |
| `/ru/rss/articles/` (все новые) | 40 айтемов ≈ 4,5 часа, сутки не покрывает |
| `/ru/rss/articles/top?fl=ru` | 40 топ-статей ~за неделю; фильтр 24 ч → 2–6 шт — выбран |

Семантика «лучшее за день» раньше жила в `best/daily`, но тот теперь 301-редиректит
на `articles/top` — поэтому «топ за сутки» = топ-лента + клиентский фильтр окна.

### 2. Пайплайн: `curl | python3` one-liner

Сырой XML (~99 KB) не влезает в лимит `exec`, поэтому фильтрация и компактизация
выполняются в том же shell-конвейере. Верифицированная команда (вкладывается в скилл
как есть, с инструкцией «выполняй без изменений»):

```bash
curl -sL --max-time 15 "https://habr.com/ru/rss/articles/top?fl=ru" | python3 -c 'import sys, xml.etree.ElementTree as ET
from datetime import datetime, timedelta, timezone
from email.utils import parsedate_to_datetime
items = ET.fromstring(sys.stdin.read()).findall(".//item")
now = datetime.now(timezone.utc)
for i in items:
    d = parsedate_to_datetime(i.findtext("pubDate"))
    if d >= now - timedelta(hours=24):
        print("%s | %s | %s" % (d.strftime("%d.%m %H:%M"), i.findtext("title"), i.findtext("link").split("?")[0]))'
```

Детали, выверенные эмпирически:

- `-L` обязателен (301-редирект со старых URL); `--max-time 15` — удвоенный
  относительно wttr.in таймаут на больший ответ.
- `pubDate` — RFC 822 в GMT; парсинг `email.utils.parsedate_to_datetime`, сравнение
  с `now(UTC) - 24h`. Дата в системном промпте тут не нужна — окно считается
  относительно текущего момента.
- `.split("?")[0]` чистит UTM-хвосты (`?utm_source=habrahabr&…`) — ссылки короче.
- Срез до 10 статей: скилл указывает «в сводку — не более 10 первых строк вывода»
  (лента уже отсортирована по рейтингу, порядок сохраняется).
- Кавычки: python-код в одинарных кавычках shell, внутри — только двойные
  (экранирование `\"` внутри `-c '…'` ломает синтаксис — проверено).
- Повтор при ошибке — по образцу wttr.in: один повтор после паузы при таймауте/5xx,
  затем деградация с пометкой в сводке.

### 3. Ссылки в сводке: HTML `<a href="…">Заголовок</a>`

`parse_mode=HTML` уже включён глобально — HTML-ссылка даёт чистый вид («заголовок
кликабелен», без голого URL в тексте). Альтернатива — голые URL — отвергнута как
шумная. Сопутствующее требование в скилл: экранировать `&`, `<`, `>` в заголовках
статей, иначе разметка сломается.

## Risks / Trade-offs

- [Habr меняет схему RSS или редиректы] → правка одного markdown-файла скилла,
  без кода и тестов; фильтр по `pubDate` устойчив к порядку элементов.
- [В топе за сутки мало статей (2–6)] → осознанный трейд-офф «кураторство vs
  полнота»; «до 10» — потолок, поведение отражено в спеке.
- [Модель перепишет команду «по-своему» и сломает кавычки] → скилл прямо требует
  выполнять команду как есть, без модификаций.
- [Блокировка User-Agent curl со стороны Habr] → сейчас не наблюдается; при
  появлении — добавить `-A` в тот же скилл.
- [Неэкранированные спецсимволы в заголовках роняют отправку] → инструкция по
  экранированию в скилле; деградация整体 сводки не блокирует.

## Migration Plan

Изменение — три markdown-файла (`skills/habr-feed.md` новый, `skills/morning.md`,
`README.md`). Развёртывание — перезапуск бота (скиллы читаются при старте).
Откат — `git revert` правки и перезапуск.

## ADDED Requirements

### Requirement: Frontmatter name и description
Каждый файл скилла SHALL начинаться с YAML frontmatter между строками
`---`, содержащего обязательные поля `name` (непустая строка) и
`description` (непустая строка: что делает скилл и когда его применять).
Поле `name` MUST совпадать с именем файла без расширения (`stem`). Тело
скилла — markdown после закрывающего `---`. Файл без корректного
frontmatter, без обязательных полей или с `name` ≠ `stem` SHALL
отклоняться при загрузке: бот MUST NOT стартовать с частично
проигнорированным каталогом (fail fast с понятной ошибкой).

#### Scenario: Корректный frontmatter
- **WHEN** бот стартует и `skills/morning.md` содержит frontmatter с
  `name: morning` и непустым `description`, а тело — после `---`
- **THEN** скилл загружается; в каталоге промпта видны `morning` и его
  description; тело доступно только через инструмент загрузки скилла

#### Scenario: name не совпадает со stem
- **WHEN** файл `skills/morning.md` содержит `name: evening` в frontmatter
- **THEN** загрузка скиллов завершается ошибкой, бот не продолжает старт
  с этим каталогом

#### Scenario: Нет description
- **WHEN** файл скилла не содержит непустого поля `description`
- **THEN** загрузка завершается ошибкой с указанием файла

### Requirement: Каталог скиллов в системном промпте
Системный промпт каждого запроса к LLM SHALL включать каталог всех
загруженных скиллов: для каждого — `name` и `description`, без тел.
Промпт SHALL содержать инструкцию: если description релевантен запросу
пользователя, загрузить полное тело инструментом `get_skill` по `name`
и следовать ему. Полные тексты скиллов MUST NOT включаться в системный
промпт. При пустом каталоге секция каталога скиллов отсутствует.

#### Scenario: В промпте только метаданные
- **WHEN** загружены скиллы `morning` и `wttr-in-api` с непустыми телами
- **THEN** системный промпт содержит их `name` и `description` и не
  содержит характерных фрагментов тел (например, конкретных curl-команд
  из тела)

#### Scenario: Инструкция активации
- **WHEN** собирается системный промпт при непустом каталоге скиллов
- **THEN** промпт явно указывает использовать `get_skill` для загрузки
  тела по имени, когда description подходит к задаче

#### Scenario: Утренняя сводка через активацию
- **WHEN** пользователь просит утреннюю сводку, а в каталоге есть скилл
  `morning` с description про утреннюю рутину
- **THEN** модель получает в system только catalog-метаданные; полное
  следование шагам рутины возможно после вызова `get_skill` с именем
  `morning` (и при необходимости связанных скиллов)

## MODIFIED Requirements

### Requirement: Каталог скиллов в корне репозитория
Скиллы SHALL храниться как markdown-файлы с YAML frontmatter в каталоге
`skills/` в корне репозитория. Бот SHALL загружать все `.md`-файлы
каталога при старте, разбирая `name`, `description` и тело. Отсутствие
или пустота каталога SHALL быть допустимыми состояниями: бот стартует
без скиллов. Некорректный frontmatter MUST NOT игнорироваться молча
(см. требование про frontmatter).

#### Scenario: Загрузка при старте
- **WHEN** бот стартует и `skills/` содержит корректные `wttr-in-api.md`
  и `morning.md`
- **THEN** оба скилла загружаются; их name и description доступны для
  каталога в системном промпте, тела — для инструмента `get_skill`

#### Scenario: Каталог без скиллов
- **WHEN** каталог `skills/` пуст или отсутствует
- **THEN** бот стартует без ошибок; системный промпт не содержит
  каталога скиллов

### Requirement: Состав скиллов домашнего задания
Репозиторий SHALL содержать три скилла домашнего задания в формате с
frontmatter: `wttr-in-api.md` (Тип A — правила использования API wttr.in
через curl: варианты формата запроса, компактный вывод, локализация,
ограничение частоты запросов), `habr-feed.md` (Тип A — правила получения
топ-ленты Habr через инструмент `exec`: источник ленты, окно за
последние сутки, ограничение количества статей, компактный вывод) и
`morning.md` (Тип B — утренняя рутина: погода в Минске → топ-статьи
Habr за сутки → итоговая сводка объёмом не более 4000 символов,
опирающаяся на правила скиллов `wttr-in-api` и `habr-feed`, которые
SHALL загружаться через `get_skill` при выполнении рутины). У каждого
SHALL быть description с триггерами WHEN (когда применять).

#### Scenario: Оба типа скиллов в репозитории
- **WHEN** проверяется каталог `skills/`
- **THEN** присутствуют `wttr-in-api.md`, `habr-feed.md` и `morning.md`
  с корректным frontmatter, и тело `morning.md` указывает загрузить
  правила `wttr-in-api` и `habr-feed` через `get_skill`

### Requirement: Стабильный префикс запроса
Системный промпт (строка reasoning-режима, строки окружения и каталог
скиллов name+description) и загруженная история сессии SHALL оставаться
неизменными между сообщениями одной сессии при неизменных скиллах:
изменение даты/времени или текущего сообщения MUST NOT менять
предшествующую часть запроса, чтобы провайдер мог кэшировать префикс.
Тела скиллов, попавшие в контекст как результаты `get_skill`, живут в
истории tool/assistant и на стабильность system-префикса не влияют.

#### Scenario: Префикс стабилен между сообщениями
- **WHEN** в одном чате обработаны два сообщения подряд без изменения
  скиллов
- **THEN** запрос для второго сообщения начинается с байтово идентичного
  префикса — системный промпт и загруженная история сессии первого запроса

#### Scenario: Префикс стабилен внутри прогона
- **WHEN** агентный цикл делает несколько LLM-вызовов в рамках одного
  сообщения
- **THEN** каждый следующий вызов начинается с того же префикса, что и
  первый, дополненного новыми сообщениями

## REMOVED Requirements

### Requirement: Скиллы в системном промпте
**Reason**: Полное тело всех скиллов в каждом запросе — основной
несокращённый вклад в input-токены; тройка оптимизаций observability не
дала −30%. Заменяется каталогом name+description и загрузкой тела через
`get_skill`.
**Migration**: См. требования «Frontmatter name и description» и
«Каталог скиллов в системном промпте»; инструмент — capability
`get-skill-tool`.

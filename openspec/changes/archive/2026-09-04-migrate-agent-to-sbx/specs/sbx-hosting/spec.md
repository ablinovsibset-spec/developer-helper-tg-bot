# sbx-hosting Delta

## Purpose

Размещение всего бота (процесс long-polling, агентный цикл, docker CLI) внутри изолированной microVM Docker Sandboxes: подготовка среды, сетевая связка с LLM на хосте, запуск, логи, обновление кода и полный сброс средствами runbook-скриптов.

## ADDED Requirements

### Requirement: Бот исполняется целиком внутри сандбокса
Бот SHALL запускаться как процесс внутри сандбокса Docker Sandboxes (microVM) с workspace-каталогом репозитория, смотрированным по его абсолютному пути хоста. Long-polling Telegram и исходящий интернет (скиллы wttr.in, Habr) SHALL работать через штатный egress-прокси сандбокса без дополнительной настройки. Сандбокс SHALL переживать остановку и повторный запуск (персистентность установленных пакетов и образов приватного docker-демона) вплоть до явного удаления.

#### Scenario: Бот отвечает изнутри сандбокса
- **WHEN** бот запущен внутри сандбокса и пользователь отправляет сообщение
- **THEN** бот получает его через long-polling и отвечает, а скиллы с исходящим интернетом (погода, Habr) работают без ошибок сети

#### Scenario: Сандбокс переживает перезапуск
- **WHEN** сандбокс остановлен и запущен снова
- **THEN** установленные внутри него пакеты и docker-образы сохраняются, повторная установка не требуется

### Requirement: Связь с LLM на хосте
Бот внутри сандбокса SHALL обращаться к LLM-серверу хоста по адресу `host.docker.internal` (порт из конфигурации LLM). Override адреса SHALL передаваться явным флагом окружения в команде запуска бота; значение из workspace-файла `.env` (localhost) SHALL NOT перекрывать его. Разрешение сетевого доступа к хостовому порту LLM выдаётся разовой командой policy при подготовке.

#### Scenario: LLM доступна через прокси сандбокса
- **WHEN** бот запущен с override `LLM_BASE_URL=http://host.docker.internal:1234/v1` и политикой `localhost:1234` разрешена
- **THEN** запросы к LLM достигают сервера на хосте, агентный цикл получает ответы модели

#### Scenario: Явный override побеждает .env
- **WHEN** workspace-файл `.env` содержит `LLM_BASE_URL` со значением `http://localhost:1234/v1`, а запуск бота передаёт иной адрес через переменную окружения
- **THEN** бот использует адрес из переменной окружения, а не из `.env`

### Requirement: Секреты бота недоступны командам агента
Границей доверия SHALL быть долгоживущий контейнер исполнения команд (см. docker-sandbox): workspace с файлом `.env` (токен Telegram) SHALL NOT быть доступным командам инструмента exec ни по одному пути. Файл `.env` SHALL оставаться не включённым в систему контроля версий.

#### Scenario: Команда агента не находит .env
- **WHEN** модель выполняет команду чтения `<workspace>/.env` инструментом exec
- **THEN** команда завершается ошибкой отсутствия пути, содержимое файла не попадает в вывод

### Requirement: Обновление кода без переустановки
Установка пакета бота внутри сандбокса SHALL быть editable: правки кода и скиллов на хосте SHALL подхватываться после перезапуска процесса бота без переустановки пакета. Виртуальное окружение SHALL размещаться на VM-локальном диске вне workspace, чтобы каталог окружения не появлялся в репозитории на хосте.

#### Scenario: Правка скилла применяется рестартом
- **WHEN** на хосте отредактирован markdown-файл скилла и процесс бота перезапущен
- **THEN** системный промпт содержит обновлённое содержимое скилла

### Requirement: Runbook-скрипты жизненного цикла
Репозиторий SHALL содержать скрипт первичной подготовки сандбокса (создание сандбокса с workspace, установка python-окружения, editable-установка пакета) и скрипт запуска бота (поднятие остановленного сандбокса, запуск процесса бота в фоне с override LLM и записью логов в VM-локальный файл). Оба сценария README SHALL описывать на уровне типовых операций (подготовка, ежедневный запуск, обновление, пауза, полный сброс).

#### Scenario: Ежедневный запуск одной командой
- **WHEN** после перезагрузки хоста выполнен скрипт запуска
- **THEN** сандбокс поднят, процесс бота запущен в фоне, бот отвечает в Telegram

#### Scenario: Логи наблюдаемы
- **WHEN** бот запущен скриптом запуска
- **THEN** журнал бота доступен внутри сандбокса в предсказуемом файле и читается командой просмотра хвоста файла

#### Scenario: Автозапуск отсутствует
- **WHEN** хост перезагружен и скрипт запуска не выполнялся
- **THEN** бот не работает; самовосстановление не производится (ручная модель восстановления)

#### Scenario: Полный сброс
- **WHEN** сандбокс удалён командой teardown и создан заново скриптом подготовки
- **THEN** персистентное состояние агента (файлы `/work`), установленные пакеты и образы начинаются с чистого листа

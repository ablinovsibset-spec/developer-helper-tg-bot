# docker-sandbox Delta

## REMOVED Requirements

### Requirement: Жизненный цикл песочницы на агентный цикл
**Reason**: Цель изменения — персистентное состояние агента: файлы и пакеты должны переживать сообщения. Контейнер «на одно сообщение» уничтожает состояние после каждого ответа.
**Migration**: Заменено требованием «Долгоживущий контейнер-жилец»: один контейнер на процесс бота, состояние переживает сообщения и `/new`.

## ADDED Requirements

### Requirement: Долгоживущий контейнер-жилец
Система SHALL использовать один контейнер исполнения на процесс бота: контейнер создаётся при первом использовании после старта бота и живёт до завершения процесса бота. Файловое состояние и установленные пакеты (`pip install --user`) SHALL переживать сообщения, границы агентных циклов и команду `/new` (сбрасывающую только контекст LLM). Удаление контейнера при завершении бота SHALL быть best-effort: ошибки удаления не SHALL прерывать завершение.

#### Scenario: Файл доступен между сообщениями
- **WHEN** при обработке одного сообщения команда создаёт файл в рабочем каталоге контейнера, а следующим сообщением пользователь просит прочитать его
- **THEN** файл успешно читается и содержит созданное содержимое

#### Scenario: Пакет переживает сообщения
- **WHEN** модель устанавливает пакет через `pip install --user` при обработке одного сообщения и использует его в любом последующем сообщении
- **THEN** пакет доступен без переустановки

#### Scenario: /new не затрагивает состояние
- **WHEN** пользователь выполняет `/new` и затем командой читает файл, созданный до сброса контекста
- **THEN** файл по-прежнему доступен: сбрасывается только история диалога LLM

#### Scenario: Контейнер удаляется при завершении бота
- **WHEN** процесс бота завершается (успешно или аварийно) и запускается снова
- **THEN** startup-последовательность нового запуска не находит контейнер прошлого запуска в работающих (уборка при штатном завершении или sweep сирот)

## MODIFIED Requirements

### Requirement: Самовосстановление после смерти песочницы
При недоступности контейнера-жителя система SHALL прозрачно пересоздать его (с чистым файловым состоянием) и повторить текущую команду один раз; работа бота MUST NOT прерываться из-за смерти контейнера. Уборка контейнера при завершении процесса бота SHALL быть best-effort: ошибки удаления не SHALL прерывать работу бота.

#### Scenario: Контейнер умер между вызовами инструмента
- **WHEN** контейнер-житель удалён внешним воздействием и модель вызывает следующий exec
- **THEN** система пересоздаёт контейнер, команда выполняется повторно, модель получает её результат, работа продолжается

#### Scenario: Ошибка уборки не роняет бота
- **WHEN** при завершении процесса бота удаление контейнера завершается ошибкой (например, docker-демон недоступен)
- **THEN** ошибка фиксируется в журнале, завершение бота продолжается

### Requirement: Окружение песочницы для скиллов
Образ контейнера-жителя SHALL содержать `curl` и `python3` со стандартной библиотекой, достаточные для выполнения верифицированных команд скиллов, и SHALL предоставлять записываемый рабочий каталог для непривилегированного пользователя. Установленные пользователем пакеты SHALL переживать сообщения в пределах жизни контейнера-жителя.

#### Scenario: Команды скиллов выполняются в песочнице
- **WHEN** модель выполняет верифицированную команду скилла `habr-feed` (curl + python3 со стандартной библиотекой)
- **THEN** команда выполняется без ошибок отсутствия утилит

#### Scenario: Установленные пакеты доступны до конца сообщения
- **WHEN** модель устанавливает пакет внутри контейнера (например, через `pip install --user`) и использует его в последующих шагах и сообщениях
- **THEN** пакет доступен до пересоздания контейнера-жителя

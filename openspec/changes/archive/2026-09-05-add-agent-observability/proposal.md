# Proposal: add-agent-observability

## Why

Агент тратит неизвестное количество токенов: `usage` приходит от поставщика в каждом
ответе, но отбрасывается при разборе (`_parse_turn`), инструментные вызовы не
измеряются вовсе. Без этих данных невозможны ни аудит потребления, ни обоснованные
оптимизации стоимости (часть 1 задания `task/observability-1.md`; оптимизации и
бенчмарк — следующие итерации).

## What Changes

- Ход ассистента (`AssistantTurn`) дополняется опциональными метаданными
  использования поставщика: input/output/cached/reasoning tokens (что провайдер
  отдал, остальное — null).
- Observing-обёртка над `LLMClient` (протокол сохраняется): фиксирует
  timestamp, model, latency, usage, turn_number каждого LLM-вызова.
- Инструментация tool-вызовов в единой точке прохождения: tool_name, input_size,
  output_size, оценочные output_tokens, duration, исход (успех/ошибка).
- Реестр прогонов: одна обработка сообщения = один run (run_id, chat_id,
  start/finish, итоговый статус); колонка label для маркировки будущих
  экспериментов «до/после».
- Хранилище телеметрии: отдельная SQLite-база (`obs.db`) по паттерну memory.db
  (aiosqlite, WAL, VM-локальный диск). Запись best-effort: сбой телеметрии
  логируется, но не роняет обработку сообщения.
- Оценка стоимости: виртуальный прайс $/1M токенов (input/output), задаётся
  конфигурацией; `estimated_cost` вычисляется на записи. Локальная модель стоит
  $0 реально — стоимость Accounting виртуальная, для сопоставимости.
- Dashboard-скрипт (`scripts/obs-dashboard.py`): агрегаты (токены по типам, cost,
  средние на задачу, cache hit rate при наличии данных, топ инструментов) и
  timeline одного прогона по ходам.

## Capabilities

### New Capabilities

- `agent-observability`: телеметрия агентных прогонов — LLM-вызовы, tool-вызовы,
  реестр прогонов, хранилище телеметрии, виртуальная оценка стоимости,
  dashboard (агрегаты + timeline прогона).

### Modified Capabilities

- `llm-provider`: контракт хода ассистента расширяется — ход MAY нести метаданные
  использования поставщика (usage), которые разбор ответа извлекает и передаёт
  вызывающему коду вместо отбрасывания.

## Impact

- Код: `llm/base.py` (AssistantTurn + usage), `llm/openai_compat.py` (извлечение
  usage), новый модуль телеметрии (обёртка, recorder, store), `config.py`
  (пути БД, прайс), `main.py` (сборка), `scripts/obs-dashboard.py` (новый).
- Поведение агента не меняется: обёртка прозрачна, записывающий код не влияет на
  ответы модели и исполнение инструментов.
- Зависимости: новых нет (aiosqlite уже используется).
- Не входит (следующие итерации): оптимизации токенов, аудит источников
  потребления, benchmark до/после, контроль success rate, команда `/stats` боту.

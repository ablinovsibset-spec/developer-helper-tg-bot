# benchmark-harness Specification Delta

## MODIFIED Requirements

### Requirement: Изоляция БД бенчмарка
Харнесс SHALL писать телеметрию в отдельный файл БД, отличный от боевой базы
observability, задаваемый параметром или переменной окружения. Боевая база
MUST NOT изменяться прогонами харнесса. Метка прогона (label) SHALL
задаваться параметром CLI с сохранением значения по умолчанию, чтобы
прогоны «до» и «после» оптимизаций можно было разделять фильтром метки
в одной БД телеметрии.

#### Scenario: Отдельная база
- **WHEN** харнесс выполняет прогон
- **THEN** записи появляются только в указанной БД бенчмарка с меткой прогона

#### Scenario: Боевая база не затронута
- **WHEN** харнесс завершил полный цикл
- **THEN** файл боевой базы телеметрии не изменился

#### Scenario: Настраиваемая метка
- **WHEN** харнесс запущен с нестандартной меткой
- **THEN** все созданные прогоны несут эту метку и фильтруются аудитом по ней

## ADDED Requirements

### Requirement: Автопроверки ответов сценариев
Харнесс SHALL автоматически проверять финальные ответы сценариев по
заявленным для каждого сценария проверкам: числовая задача — ожидаемое
число в ответе; многоходовая сессия — упоминание зафиксированных на раннем
шаге сущностей; файловая задача — упоминание сути найденного бага. Результат
каждой проверки SHALL выводиться по завершении шага; провал проверки SHALL
маркироваться явно и отдельно от статуса завершения прогона.

#### Scenario: Верный ответ проходит проверку
- **WHEN** финальный ответ сценария удовлетворяет заявленным проверкам
- **THEN** шаг выводится как прошедший проверки

#### Scenario: Неверный ответ проваливает проверку
- **WHEN** финальный ответ сценария не удовлетворяет проверке
- **THEN** в выводе харнесса шаг явно маркирован как проваленный проверкой,
  при этом статус прогона в телеметрии отражает завершение цикла агента

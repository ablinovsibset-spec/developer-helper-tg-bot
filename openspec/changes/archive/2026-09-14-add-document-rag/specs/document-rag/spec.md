## Purpose

Даёт пользователю загрузку документов в Telegram-бота, индексацию через собственный RAG (chunking + embeddings + SQLite/sqlite-vec) и ответы агента на вопросы по документам с изоляцией владельца, attribution и безопасным отказом при отсутствии фактов.

## ADDED Requirements

### Requirement: Индексация загруженного документа
Система SHALL принимать документ поддерживаемого типа (`.txt`, `.md`, `.docx`, `.pdf`), извлекать текст, разбивать на chunks, получать embeddings и сохранять документ, chunks и векторы в персистентном хранилище. При успехе пользователь MUST получить подтверждение готовности; при старте обработки — уведомление о начале.

#### Scenario: Успешная индексация
- **WHEN** пользователь отправляет поддерживаемый документ в пределах лимитов размера
- **THEN** бот сообщает о начале обработки, индексирует документ и сообщает, что можно задавать вопросы по документу

#### Scenario: Неподдерживаемый формат
- **WHEN** пользователь отправляет файл с неподдерживаемым расширением
- **THEN** бот отвечает понятным сообщением об ошибке и не индексирует файл

#### Scenario: Повреждённый или пустой документ
- **WHEN** извлечение текста завершается ошибкой или даёт пустой текст
- **THEN** бот отвечает понятным сообщением об ошибке и не оставляет частичный индекс документа

### Requirement: Лимиты размера документа
Система SHALL отклонять документы, превышающие настроенные лимиты сырого размера файла, объёма извлечённого текста или числа chunks после разбиения, с понятным сообщением пользователю.

#### Scenario: Слишком большой файл
- **WHEN** размер загружаемого файла превышает лимит сырых байт
- **THEN** бот отказывает в обработке до индексации и сообщает о превышении лимита

#### Scenario: Слишком большой извлечённый текст
- **WHEN** после извлечения текст или число chunks превышает лимит
- **THEN** бот не сохраняет документ в индекс и сообщает о превышении лимита

### Requirement: Несколько документов и replace по имени
Пользователь SHALL иметь возможность хранить несколько документов. Повторная загрузка файла с тем же именем для того же владельца MUST заменить предыдущую версию: старые chunks и embeddings удаляются, затем выполняется новая индексация.

#### Scenario: Несколько документов у одного пользователя
- **WHEN** пользователь последовательно загружает два файла с разными именами
- **THEN** оба документа доступны для поиска этого пользователя

#### Scenario: Replace при том же имени
- **WHEN** пользователь загружает документ с именем, уже существующим у него в индексе
- **THEN** предыдущая версия удаляется из индекса вместе с chunks и embeddings, а новая версия становится единственной с этим именем

### Requirement: Изоляция документов по владельцу
Поиск и команды управления документами MUST учитывать владельца документа (Telegram user id). Документы одного пользователя MUST NEVER использоваться при ответе другому пользователю.

#### Scenario: Чужой документ не находится
- **WHEN** пользователь A загрузил документ, а пользователь B задаёт вопрос, ответ на который есть только в документе A
- **THEN** поиск для B не возвращает chunks документа A

### Requirement: Инструмент search_documents
Агент SHALL иметь инструмент поиска по документам текущего пользователя. Retrieval MUST выполняться через этот инструмент по запросу модели, а не путём постоянной подстановки всех документов в system prompt. Результат инструмента SHALL содержать релевантные chunks и имена исходных файлов (и при наличии — индекс chunk).

#### Scenario: Модель вызывает поиск
- **WHEN** пользователь спрашивает о содержании загруженных документов и модель вызывает `search_documents`
- **THEN** инструмент возвращает Top-K релевантных chunks только из документов этого пользователя

#### Scenario: Пустой результат поиска
- **WHEN** поиск не находит релевантных chunks
- **THEN** инструмент сообщает об отсутствии результатов, а ответ пользователю MUST NOT выдавать общие знания модели как факты из документа

### Requirement: Source attribution в ответах по документам
Когда ответ опирается на найденные chunks, финальный ответ пользователю SHALL указывать источник как минимум в форме имени файла документа.

#### Scenario: Ответ со ссылкой на файл
- **WHEN** агент отвечает на вопрос на основе chunks из `vacation_policy.pdf`
- **THEN** ответ содержит указание источника с именем `vacation_policy.pdf`

### Requirement: Команда /documents
Бот SHALL обрабатывать команду `/documents` отдельным обработчиком (не через агентный цикл) и показывать список имён документов текущего пользователя.

#### Scenario: Список документов
- **WHEN** у пользователя есть загруженные документы и он отправляет `/documents`
- **THEN** бот отвечает списком имён этих документов без вызова LLM

#### Scenario: Пустой список
- **WHEN** у пользователя нет документов и он отправляет `/documents`
- **THEN** бот сообщает, что документов нет

### Requirement: Команда /delete по имени файла
Бот SHALL обрабатывать `/delete <filename>` отдельным обработчиком и удалять документ текущего пользователя с этим именем вместе с его chunks и embeddings. После удаления документ MUST NOT участвовать в retrieval.

#### Scenario: Успешное удаление
- **WHEN** пользователь отправляет `/delete vacation_policy.pdf` для своего существующего документа
- **THEN** документ, его chunks и embeddings удаляются, и бот подтверждает удаление

#### Scenario: Документ не найден
- **WHEN** пользователь отправляет `/delete` с именем, которого нет среди его документов
- **THEN** бот сообщает, что документ не найден, и не меняет индекс

#### Scenario: Удаление без аргумента
- **WHEN** пользователь отправляет `/delete` без имени файла
- **THEN** бот отвечает подсказкой по использованию команды

### Requirement: Персистентность индекса на VM-локальном диске
Индекс документов SHALL храниться в отдельном файле БД на VM-локальном диске (путь настраивается окружением) и переживать рестарт процесса бота. Workspace-маунт MUST NOT использоваться как расположение по умолчанию для этого файла.

#### Scenario: Индекс после рестарта
- **WHEN** бот перезапущен после успешной индексации документа
- **THEN** документ по-прежнему доступен через `/documents` и `search_documents` для того же пользователя

# llm-provider Delta

## MODIFIED Requirements

### Requirement: Единый контракт вызова LLM
Доступ к LLM SHALL предоставляться через единый контракт, принимающий список сообщений диалога, опциональный набор описаний инструментов и опциональное указание формата ответа (response_format), и возвращающий ход ассистента, состоящий из финального текста и/или вызовов инструментов. Указание формата ответа SHALL пробрасываться поставщику, когда тот его поддерживает; для поставщика без поддержки контракт SHALL отправлять запрос без указания формата, не считая это ошибкой. Вызывающий код MUST NOT знать о конкретном поставщике, формате его API или сетевых деталях. Сообщения диалога SHALL поддерживать роли `system`, `user`, `assistant` и `tool`; сообщения `assistant` MAY нести вызовы инструментов, сообщения `tool` — результат конкретного вызова по его идентификатору. Вызов без инструментов SHALL оставаться семантически эквивалентным прежнему одноходовому вызову.

#### Scenario: Вызов с одним пользовательским сообщением
- **WHEN** вызывающий код передаёт список из одного user-сообщения без описаний инструментов
- **THEN** контракт возвращает ход ассистента с финальным текстом и пустым списком вызовов инструментов

#### Scenario: Вызов с инструментами
- **WHEN** переданы описания инструментов и модель решает воспользоваться инструментом
- **THEN** контракт возвращает ход ассистента с пустым текстом и непустым списком вызовов инструментов

#### Scenario: Вызов с указанием формата ответа
- **WHEN** вызывающий код передаёт указание формата ответа (например JSON-схему), а поставщик его поддерживает
- **THEN** запрос к поставщику содержит соответствующее поле формата ответа

#### Scenario: Изоляция поставщика
- **WHEN** меняется поставщик LLM (LM Studio → Ollama → OpenAI)
- **THEN** вызывающий код не изменяется

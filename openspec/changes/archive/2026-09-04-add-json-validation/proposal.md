## Why

Когда модель отдаёт сломанный структурированный ответ, единственный механизм «переделай» — ошибки аргументов инструментов, возвращаемые в общий бюджет 8 шагов и заканчивающиеся безликим STEPS_EXHAUSTED. Нет единой точки валидации, отдельного счётчика провалов, различения чинибельных/нечинибельных ошибок и поддержки `response_format` на шве LLMClient.

## What Changes

- Обобщённый механизм валидации структурированных (JSON) ответов модели в агентном цикле; существующая валидация аргументов `exec` становится частным случаем.
- Retry через внешний цикл: битый ответ остаётся в истории + рядом сообщение с конкретной ошибкой разбора и требованием к формату.
- Отдельный счётчик подряд идущих провалов валидации (2–3) с терминальным сообщением «модель не смогла сформировать корректный ответ» — отличимым от сообщения об исчерпании шагов.
- `finish_reason == "length"` (ответ оборван лимитом токенов) терминалится сразу, без ретраев: фидбек не чинит обрыв.
- Первый рубеж обороны: опциональный `response_format: json_schema` для запросов, где требуется JSON-ответ; retry-with-feedback остаётся fallback для провайдеров без поддержки.
- Контракт LLMClient расширяется опциональным параметром `response_format`; провайдер без поддержки деградирует до retry, а не падает.
- Точка расширения: валидатор финального текстового ответа (пока no-op — появится вместе с первым потребителем финального JSON).

## Capabilities

### New Capabilities

- `response-validation`: эшелонированная валидация структурированных ответов LLM — грамматика/схема первым рубежом, валидатор в агентном цикле, retry-with-feedback через историю, счётчик провалов и терминальное поведение.

### Modified Capabilities

- `llm-provider`: требование «Единый контракт вызова LLM» расширяется — контракт опционально принимает `response_format` и пробрасывает его OpenAI-совместимым поставщикам.

## Impact

- **Код**: `agent.py` (валидатор ходов, счётчик, терминалы, фидбек-сообщения), `llm/base.py` (сигнатура контракта + `response_format`), `llm/openai_compat.py` (проброс в payload), вынос общей JSON-валидации из `execute_tool_call`.
- **Зависимости**: новых нет; `response_format` — поле существующего OpenAI-совместимого API.
- **Существующее поведение**: сообщения об ошибках аргументов инструментов не меняются (модель по-прежнему видит ошибку как tool-сообщение); меняется только терминальное поведение при серии провалов.
- **Риск для проверки на живой модели** (фиксируется в design.md): `json_schema` может подавлять tool-calling у мелких моделей — возможно точечное применение только к финальным шагам.

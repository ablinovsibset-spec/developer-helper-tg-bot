## Context

Системный промпт собирается в `skills.py` (`build_system_prompt`/`system_prompt_from_dir`) из строки `Reasoning: medium` и секций скиллов, а в `main.py` замораживается один раз при старте (`dp["system_prompt"]`) и вставляется первым сообщением контекста при его создании (`chat_history`). В долгом диалоге промпт (а с ним и любая дата) остаётся неизменным до `/new`. Часовой пояс — локальное время сервера (решение пользователя); обновление — при каждом сообщении пользователя.

## Goals / Non-Goals

**Goals:**

- Системный промпт каждого запроса содержит актуальные локальные дату/время сервера с точностью до минуты и день недели.
- Детерминированное тестирование форматирования без реальных часов и без locale-зависимости.

**Non-Goals:**

- Часовой пояс пользователя (Telegram не отдаёт надёжно) — только локальное время сервера.
- Обновление даты между tool-шагами одного агентного цикла — достаточно точности «на сообщение пользователя».
- Горячая перезагрузка каталога `skills/` — скиллы по-прежнему читаются один раз при старте.

## Decisions

### 1. Чистая сборка промпта с инъекцией момента времени

`build_system_prompt(skills, now: datetime | None = None)` и `system_prompt_from_dir(skills_dir, now=None)`: без `now` берётся `datetime.now()` (локальное время сервера). Тесты передают фиксированный `datetime` и получают точную строку. Альтернатива — патчить глобальные часы в тестах — отвергнута как хрупкая.

### 2. Формат строки и её место в промпте

Строка `Текущие дата и время: 2026-08-28 07:45 (четверг)` ставится второй — после `Reasoning: medium`, перед секциями скиллов:

```
Reasoning: medium
Текущие дата и время: 2026-08-28 07:45 (четверг)

## wttr-in-api
...
```

Дата/время — машинно-однозначный формат `%Y-%m-%d %H:%M` (без секунд: точность до минуты достаточна, меньше шума). День недели — из собственного кортежа `("понедельник", …)`, а не `strftime('%A')`: встроенная локаль зависит от окружения ОС и ломает детерминизм тестов. Альтернатива — русская локаль через `locale.setlocale` — глобально мутирует состояние процесса и ненадёжна на разных машинах.

### 3. Обновление системного сообщения в истории на каждое сообщение

В `main.py` вместо замороженной строки в `dp` хранится словарь скиллов: `dp["skills"] = load_skills(default_skills_dir())`. Обработчик `handle_text` перед добавлением user-сообщения собирает свежий промпт `build_system_prompt(skills, datetime.now())` и обновляет системное сообщение: если истории нет — создаёт `[system]`; если есть — перезаписывает содержимое `history[0]` (роль и позиция не меняются, остальная история не трогается). `chat_history` меняет контракт с «вставить при создании контекста» на «гарантировать актуальное системное сообщение первым».

Альтернативы, отвергнутые:
- Пересборка промпта только при старте — время устаревает (нарушает требование обновления).
- Дата отдельным system-сообщением в истории — два system-сообщения в одном запросе без необходимости.
- Хранение в `dp` фабрики промптов вместо словаря скиллов — лишний слой косвенности ради одной строки.

Часы для тестов `main` — модульный атрибут `dev_helper_bot.main.datetime` (main импортирует `from datetime import datetime`), патчится `monkeypatch.setattr` фейком с управляемым `now()`.

## Risks / Trade-offs

- [Локальное время сервера может отличаться от пояса пользователя] → принято осознанно (решение пользователя); при переносе бота на другой хост время сменится вместе с сервером.
- [Тесты на реальных часах флаки на границе минуты] → все проверки формата и обновления идут на фиксированном/фейковом времени.
- [Мутация `history[0]` на месте] → перезаписывается только `content` системного сообщения; порядок и остальные сообщения контекста не меняются, что закрывается тестом «история сохраняется между сообщениями».

## Migration Plan

Изменение затрагивает только формирование промпта в памяти: без миграций данных и конфигурации. Развёртывание — перезапуск бота; откат — revert коммита.

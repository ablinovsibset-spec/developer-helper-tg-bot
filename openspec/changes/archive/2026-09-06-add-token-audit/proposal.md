# Proposal: add-token-audit

## Why

Инфраструктура телеметрии (change add-agent-observability) собирает токены по
каждому LLM-вызову и инструменту, но в базе нет ни одного прогона, а аудит
«кто съедает токены» (Часть 2 задачи observability) нечем считать: четыре
вопроса аудита — топ инструментов, самый дорогой ход, рост типов контекста,
доля повторно отправляемых токенов — требуют воспроизводимых данных и разбивки
промпта по ролям, которой сейчас нет.

## What Changes

- Телеметрия LLM-вызова дополняется JSON-колонкой `prompt_roles` — разбивкой
  промпта в символах по ролям сообщений (system/user/assistant/tool); миграция
  через `ALTER TABLE`, старые записи остаются с null.
- Новый benchmark-харнесс `scripts/obs-benchmark.py`: гоняет агента напрямую
  через `run_agent` (мимо Telegram) по фиксированному набору сценариев с
  реальным LLM и Docker-песочницей, пишет телеметрию в отдельную БД.
- Фикстура-проект (небольшой python-проект с файлами и тестами) создаётся в
  песочнице для файловых сценариев.
- Новый аудит-скрипт `scripts/obs-audit.py`: отвечает на четыре вопроса Части 2
  по данным БД — топ инструментов по токенам, самый дорогой ход, рост типов
  контекста по `prompt_roles`, повторно отправляемые токены (внутрипрогонно и
  межпрогонно), с ASCII-барами в формате задачи.
- Отчёт «до»: зафиксированные цифры аудита становятся baseline для оптимизаций
  Части 3.

## Capabilities

### New Capabilities

- `benchmark-harness`: воспроизводимая генерация телеметрии — фиксированные
  сценарии, прогон агента напрямую с реальным LLM и песочницей, фикстура
  тестового проекта, изоляция БД бенчмарка от боевой.
- `token-audit`: CLI-аудит потребления токенов по БД телеметрии — четыре
  вопроса Части 2 с толерантностью к отсутствующим данным.

### Modified Capabilities

- `agent-observability`: требование «Телеметрия LLM-вызовов» расширяется —
  каждая запись дополняется разбивкой промпта по ролям сообщений (символы на
  role: system/user/assistant/tool), отсутствие разбивки допустимо только для
  записей, созданных до миграции.

## Impact

- `src/dev_helper_bot/telemetry.py`: схема `_SCHEMA` + миграция `prompt_roles`,
  расчёт разбивки в `ObservingClient.complete()`, поле в `LLMCallRecord`.
- `scripts/obs-benchmark.py`, `scripts/obs-audit.py`: новые самодостаточные
  CLI-скрипты (как `obs-dashboard.py`).
- Docker-песочница: фикстура-проект для файловых сценариев.
- `tests/`: юнит-тесты разбивки ролей и миграции; смоук-проверки скриптов
  на временной БД.
- Не затрагивает: агентный цикл, контракт LLMClient, память сессий, Telegram-слой.

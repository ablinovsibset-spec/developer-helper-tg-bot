# Proposal: minimal-agent

## Why

Курсовое домашнее задание требует превратить одноходового бота-пересыльщика в минимального автономного агента: модель должна выполнять реальные действия в системе через инструмент `exec`, следовать текстовым скиллам и вести диалог в рамках одного длинного контекста. Модель переводится на gpt-oss-20b, чей native tool-calling проверен probe'ом на целевой машине (полный круг `tool_calls → tool → финал` через LM Studio работает).

## What Changes

- Агентный цикл (harness): циклическая обработка вызовов модели до финального ответа, максимум 8 шагов, сигнал завершения по `finish_reason`, честное сообщение при исчерпании шагов.
- **BREAKING** (для контракта): `LLMClient.complete` расширяется до `complete(messages, tools=None) -> AssistantTurn`, где `AssistantTurn` несёт `content` и `tool_calls`; `Message` расширяется полями `tool_calls` / `tool_call_id` (роли `assistant` с вызовами и `tool` с результатами). Без `tools=` вызов остаётся совместимым по смыслу, но возвращаемый тип меняется — существующие стабы и тесты адаптируются.
- Универсальный инструмент `exec`: выполнение консольных команд (subprocess), таймаут 30с, обрезка вывода до ~3000 символов (голова+хвост); stdout/stderr/код выхода, включая ошибки, возвращаются модели как результат вызова.
- Скиллы: каталог `skills/` в корне репозитория; `wttr-in-api.md` (Тип A — инструкция к API) и `morning.md` (Тип B — утренняя рутина, опирается на A); склейка всех `.md` в системный промпт при старте.
- Память диалога: чат — один длинный контекст, in-memory, включает инструментный транскрипт, но не reasoning; команда `/new` сбрасывает контекст чата. Требование «Одноразовый контекст без памяти» инвертируется.
- UX цикла: сообщение «⏳ Готовлю ответ…» в начале агентного цикла; финальный ответ — новым сообщением (чанкинг 4096 сохраняется).
- Конфигурация: модель по умолчанию `openai/gpt-oss-20b`, таймаут LLM по умолчанию 120с, reasoning effort `medium`.
- Осознанные non-goals: allowlist пользователей (бот остаётся открытым — решение принято), персистентность истории между рестартами, показ reasoning и пошаговой трассы пользователю.

## Capabilities

### New Capabilities

- `agent-loop`: агентный цикл — оркестрация «вызов модели → выполнение tool_calls → результат в историю → повтор», предел 8 шагов, поведение при исчерпании.
- `exec-tool`: универсальный инструмент `exec` — контракт вызова из модели, выполнение через subprocess с таймаутом, обрезка вывода, возврат ошибок модели.
- `skills`: скиллы `skills/*.md` — состав, расположение, загрузка при старте, встраивание в системный промпт.

### Modified Capabilities

- `telegram-bot`: требование «Одноразовый контекст без памяти» заменяется на «Один длинный контекст на чат» (с инструментным транскриптом, без reasoning); добавляются команда `/new` и сообщение ожидания «⏳» на время агентного цикла.
- `llm-provider`: контракт `LLMClient` расширяется tool-calling (параметр `tools`, возврат `AssistantTurn` с `tool_calls`, сообщения роли `tool`); OpenAI-совместимая реализация поддерживает полный tool-call round-trip; значения по умолчанию — модель `openai/gpt-oss-20b`, таймаут 120с.
- `test-suite`: добавляется автоматическая проверка агентного цикла, инструмента exec, скиллов и памяти; сценарий «Проверка отсутствия памяти» инвертируется в проверку сохранения контекста и сброса по `/new`.

## Impact

- Код: `llm/base.py` и `llm/openai_compat.py` (tool-calling, таймаут, parsing `tool_calls`/`arguments`-JSON); новые модули `agent.py`, `tools.py`, `skills.py`; `main.py` (память чатов, `/new`, «⏳»); `config.py` (новые дефолты, effort).
- Новые каталоги: `skills/` в корне репозитория (два файла скиллов).
- Тесты: инверсия `test_handle_text_no_memory_between_messages`; FakeLLM-стаб эволюционирует в последовательность ходов (`tool_calls` → финал); фейковый exec; новый фейковый HTTP-ответ с `tool_calls` в integration-тестах.
- Конфигурация: `.env.example` (`LLM_MODEL=openai/gpt-oss-20b`), README (агентный режим, `/new`, скиллы).
- Зависимости: новых нет — `asyncio.subprocess` из stdlib.
- Риски: exec без allowlist выполняет команды от любого пользователя бота (принято осознанно); reasoning-модель медленнее одноходового ответа — закрыто сообщением ожидания и таймаутом 120с.

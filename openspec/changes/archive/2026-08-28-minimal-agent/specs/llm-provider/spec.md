# llm-provider Delta

## MODIFIED Requirements

### Requirement: Единый контракт вызова LLM
Доступ к LLM SHALL предоставляться через единый контракт, принимающий список сообщений диалога и опциональный набор описаний инструментов, и возвращающий ход ассистента, состоящий из финального текста и/или вызовов инструментов. Вызывающий код MUST NOT знать о конкретном поставщике, формате его API или сетевых деталях. Сообщения диалога SHALL поддерживать роли `system`, `user`, `assistant` и `tool`; сообщения `assistant` MAY нести вызовы инструментов, сообщения `tool` — результат конкретного вызова по его идентификатору. Вызов без инструментов SHALL оставаться семантически эквивалентным прежнему одноходовому вызову.

#### Scenario: Вызов с одним пользовательским сообщением
- **WHEN** вызывающий код передаёт список из одного user-сообщения без описаний инструментов
- **THEN** контракт возвращает ход ассистента с финальным текстом и пустым списком вызовов инструментов

#### Scenario: Вызов с инструментами
- **WHEN** переданы описания инструментов и модель решает воспользоваться инструментом
- **THEN** контракт возвращает ход ассистента с пустым текстом и непустым списком вызовов инструментов

#### Scenario: Изоляция поставщика
- **WHEN** меняется поставщик LLM (LM Studio → Ollama → OpenAI)
- **THEN** вызывающий код не изменяется

### Requirement: Поддержка OpenAI-совместимых поставщиков
Система SHALL предоставлять реализацию контракта для OpenAI-совместимых эндпоинтов (`/v1/chat/completions`), параметризуемую базовым URL, именем модели и опциональным API-ключом. Реализация SHALL покрывать LM Studio, Ollama (через `/v1`), vLLM и OpenAI без изменения кода, включая передачу описаний инструментов и полный tool-call round-trip: проброс `tools` в запрос, разбор `tool_calls` из ответа (включая аргументы как JSON-строку) и сериализацию истории с ролями `assistant` (с `tool_calls`) и `tool` (с `tool_call_id`) в последующих запросах.

#### Scenario: Локальный LM Studio без API-ключа
- **WHEN** конфигурация указывает `LLM_BASE_URL=http://localhost:1234/v1` и модель `openai/gpt-oss-20b` без API-ключа
- **THEN** запросы идут к локальному LM Studio без заголовка авторизации

#### Scenario: Облачный OpenAI-совместимый поставщик с ключом
- **WHEN** конфигурация указывает облачный `LLM_BASE_URL` и `LLM_API_KEY`
- **THEN** запросы идут к облачному поставщику с заголовком `Authorization: Bearer <key>`

#### Scenario: Round-trip вызова инструмента
- **WHEN** модель отвечает вызовом инструмента (`finish_reason=tool_calls`, аргументы как JSON-строка)
- **THEN** реализация возвращает ход с разобранными вызовами инструментов, а при передаче в следующий вызов истории с assistant-сообщением (с `tool_calls`) и tool-сообщением (с `tool_call_id`) поставщик принимает запрос и возвращает финальный ответ

### Requirement: Конфигурация только через окружение
Все параметры LLM (`LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`) SHALL читаться из переменных окружения / `.env` и MUST NOT захардкоживаться в исходном коде.

#### Scenario: Значения по умолчанию
- **WHEN** `LLM_BASE_URL` и `LLM_MODEL` не заданы
- **THEN** используются значения по умолчанию для локального LM Studio (`http://localhost:1234/v1`) и модели `openai/gpt-oss-20b`

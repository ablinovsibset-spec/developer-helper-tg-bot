## Context

Живой код: `main.py` (`send_chunked`, `handle_text`, `main`), `config.py` (`make_llm`, `telegram_token`), `llm/openai_compat.py` (`OpenAICompatibleClient` на aiohttp). Тестовый каркас `tests/{unit,integration}/` существует, но пуст. Конфигурация читается напрямую из `os.environ` — `load_dotenv()` вызывается только в `main()`, поэтому конфиг-функциции тестируются через `monkeypatch.setenv/delenv` без вмешательства в код. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- Детерминированный набор тестов: без сети (кроме localhost), без секретов, без LLM Studio и Telegram.
- Зеркальная структура: `tests/unit/` и `tests/integration/` повторяют `src/dev_helper_bot/`.
- Минимум новых зависимостей: только `pytest` + `pytest-asyncio`.

**Non-Goals:**
- E2E-тесты с реальным Telegram API или LM Studio.
- Настройка coverage-порогов и CI (можно добавить позже отдельным change).
- Рефакторинг живого кода; правки допускаются только при реальной необходимости для тестируемости.

## Decisions

### 1. pytest-asyncio с `asyncio_mode = "auto"`
Асинхронных тестов большинство (обработчики, HTTP-клиент). Auto-режим избавляет от `@pytest.mark.asyncio` на каждом тесте.
*Альтернативы:* `anyio` (второй плагин в экосистеме pytest — лишняя сущность для учебного проекта); голый `asyncio.run` в тестах (теряются фикстуры и изоляция).

### 2. Fake-объекты для тестов обработчика вместо мок-фреймворка
`handle_text` использует от `Message` только `.text` и `.chat.id`, от `Bot` — `send_message`. Пишем маленькие fake-классы (записывают вызовы в списки), duck typing достаточен — aiogram-типы не проверяются во время выполнения.
*Альтернативы:* `unittest.mock.AsyncMock` (громоздкие утверждения, хуже читается); официальные тест-утилиты aiogram (тянут лишние зависимости, привязка к версии).

### 3. Фейковый LLM-сервер на aiohttp для integration-тестов `OpenAICompatibleClient`
Локальный HTTP-сервер на произвольном порту имитирует `/v1/chat/completions`: управляемый статус, тело ответа, задержка. Прогоняется реальный код клиента по реальному стеку aiohttp — включая таймауты и заголовки, которые сервер может инспектировать.
*Альтернативы:* `aioresponses` (патчит внутренности aiohttp, не проверяет реальный сетевой путь); `responses` (для requests, не подходит).

### 4. Таймаут тестируем через задержку сервера + маленький timeout клиента
Клиенту передаём `timeout=0.2`, сервер отвечает с `asyncio.sleep(1)`. Тест занимает <1 сек и не флактуирует.
*Альтернатива:* патчить `aiohttp.ClientTimeout` — хрупко.

### 5. Конфиг-тесты через `monkeypatch`
`monkeypatch.delenv/setenv` для `LLM_*` и `TELEGRAM_BOT_TOKEN`. Гарантирует изоляцию от `.env` разработчика без правок кода (см. Context).

### 6. Удаление заглушек после проверки отсутствия импортов
Перед удалением `models.py`/`services.py`/`utils.py` — `grep` по репозиторию на импорты. Заглушки нигде не импортируются (код проекта их не использует), риск нулевой.

## Risks / Trade-offs

- [Fake-объекты разъезжаются с реальными типами aiogram при мажорном обновлении] → обработчик использует минимальную поверхность API (`.text`, `.chat.id`, `send_message`); расхождение заметно сразу при обновлении.
- [`pytest-asyncio` strict-режим по умолчанию в новых версиях] → явно задаём `asyncio_mode = "auto"` в `pyproject.toml`.
- [Порт фейкового сервера занят] → `aiohttp.test_utils`/привязка к порту 0 (ОС выделяет свободный).
- [Тесты хрупки к формату ответа OpenAI] → фиксируем минимальный валидный JSON `choices[0].message.content`; это и есть контракт провайдера.

## Migration Plan

1. Добавить dev-зависимости и настройки pytest.
2. Написать unit-тесты (`main`, `config`, затем integration `llm`).
3. Удалить заглушки, вычистить локальный мусор (`__pycache__` в корне, `.egg-info`).
4. Прогон `pytest` — зелёный; `pip install -e .` по-прежнему работает.

Откат тривиален: тесты и зависимости удаляются, заглушки восстанавливаются из git.

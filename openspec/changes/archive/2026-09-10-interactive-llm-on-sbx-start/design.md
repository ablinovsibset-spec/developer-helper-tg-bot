## Context

Сейчас `scripts/sbx-start.sh` всегда передаёт `-e LLM_BASE_URL=http://host.docker.internal:${LLM_PORT}/v1` (дефолт порт 1234), а `LLM_MODEL` / `LLM_API_KEY` процесс читает из workspace-`.env` через `load_dotenv()`. Мотивация изменения — proposal.md (Why): рассинхрон при облачном `.env` и молчаливом LM Studio override. Python-фабрика `make_llm()` уже уважает заранее заданное окружение (dotenv не перезаписывает существующие ключи) — меняется только runbook-скрипт и документация.

## Goals / Non-Goals

**Goals:**
- Интерактивный confirm трёх LLM-параметров при каждом `sbx-start.sh`.
- Дефолты всегда LM Studio + `openai/gpt-oss-20b` + пустой ключ (не содержимое `.env`).
- Проброс всех трёх значений в процесс через `sbx exec -e`, без записи в `.env`.

**Non-Goals:**
- Флаг `-y` / автоматический skip для non-TTY.
- Пресеты (меню LM Studio / Ollama / routerai) — свободный ввод URL.
- Автодописывание `sbx policy` при смене порта (остаётся зона `sbx-setup` / ручной policy).
- Изменения `config.py`, агентного цикла, границы доверия `.env`.

## Decisions

### D1: Промпты в bash до `sbx exec`, не в Python
Спрашивать в `sbx-start.sh` через `read -r` (для ключа — `read -rs`), показывать дефолт в `[…]`. Скрипт и так владеет lifecycle запуска; тянуть отдельный CLI в пакет избыточно.

Альтернатива «спрашивать при старте `main.py`» отвергнута: бот в фоне без TTY, а вопросы нужны оператору на хосте.

### D2: Дефолты фиксированные (LM Studio), не из `.env`
Suggested values:
- `LLM_BASE_URL` → `http://host.docker.internal:1234/v1` (как сейчас; `LLM_PORT` может участвовать в сборке дефолтного URL, если уже задан в окружении вызывающего shell — иначе 1234)
- `LLM_MODEL` → `openai/gpt-oss-20b`
- `LLM_API_KEY` → пустая строка

Если в shell уже экспортированы `LLM_*` до вызова скрипта — использовать их как pre-filled defaults в `[…]` (удобство), но при «чистом» запуске без экспорта — всегда LM Studio-набор, даже когда `.env` указывает на routerai.

Альтернатива «дефолт = `.env`» отвергнута явно (explore): цель — безопасный локальный стек по Enter, а не воспроизведение файла.

### D3: Все три переменные уходят в `-e`
Сейчас в `sbx exec` уходит только `LLM_BASE_URL` (+ `OBS_WEB_HOST`). После change — также `LLM_MODEL` и `LLM_API_KEY` (пустой ключ тоже передавать явно, чтобы облачный ключ из `.env` не «протекал» в локальный LM Studio-сеанс после Enter×3).

`OBS_WEB_HOST=0.0.0.0` без изменений.

### D4: Без тихого режима
Оператор всегда отвечает в терминале. Non-TTY / CI не в scope (согласовано). Если stdin не TTY — допустимо падение/`read` EOF; отдельную обработку не проектируем.

### D5: Секреты в выводе
Ключ не эхоить при вводе (`read -s`). В `say` после confirm печатать URL и model; для ключа — только `set` / `empty`, не значение.

### D6: README
Обновить раздел ежедневного запуска: интерактивный confirm, пример Enter×3 = LM Studio, пример ввода облачного URL/модели/ключа с клавиатуры; убрать акцент на «только `LLM_BASE_URL=…` перед скриптом» как основной способ смены провайдера (env pre-fill остаётся рабочим через D2, но не единственным путём).

## Risks / Trade-offs

- [Облачный ключ в `.env` больше не используется, пока оператор не введёт его в prompt] → ожидаемо: сеанс изолирован; для облака нужно ввести ключ (или заранее экспортировать `LLM_API_KEY` в shell как pre-fill).
- [Смена порта хоста без policy] → как сегодня при `LLM_PORT=…`; предупреждение в README / комментарии скрипта достаточно.
- [Ключ в истории процесса / `ps` через `sbx exec -e`] → кратковременно в argv/env контейнера exec; не пишем в файл; приемлемо для учебного runbook.
- [«Одна команда» из старой спеки → команда + Enter×3] → осознанный trade-off ради явного выбора LLM.

## Migration Plan

1. Обновить `scripts/sbx-start.sh` и README.
2. Оператору: привычный `scripts/sbx-start.sh` + Enter×3 для LM Studio; для routerai — ввести URL/модель/ключ в промптах (`.env` можно оставить как справочный/host-режим).
3. Откат: вернуть прежний `sbx-start.sh` (только `-e LLM_BASE_URL`).

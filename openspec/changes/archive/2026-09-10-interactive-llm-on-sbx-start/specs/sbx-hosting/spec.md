## ADDED Requirements

### Requirement: Интерактивный выбор LLM при запуске
Скрипт запуска бота внутри сандбокса SHALL перед стартом процесса интерактивно запросить у оператора `LLM_BASE_URL`, `LLM_MODEL` и `LLM_API_KEY`. Предлагаемые по умолчанию значения SHALL быть: URL LM Studio внутри VM (`http://host.docker.internal:1234/v1`), модель `openai/gpt-oss-20b`, пустой API-ключ. Пустой ввод (Enter) SHALL принимать соответствующий дефолт. Выбранные значения SHALL передаваться в процесс бота явными переменными окружения запуска и SHALL NOT записываться скриптом в workspace-файл `.env`.

#### Scenario: Дефолты LM Studio принимаются Enter
- **WHEN** оператор запускает скрипт старта в терминале и трижды нажимает Enter на запросах URL, модели и ключа
- **THEN** процесс бота стартует с `LLM_BASE_URL=http://host.docker.internal:1234/v1`, `LLM_MODEL=openai/gpt-oss-20b` и пустым `LLM_API_KEY`

#### Scenario: Оператор подставляет облачный endpoint
- **WHEN** оператор на запросах вводит облачный `LLM_BASE_URL`, имя модели и API-ключ
- **THEN** процесс бота стартует с введёнными значениями через переменные окружения запуска

#### Scenario: .env не переписывается скриптом
- **WHEN** оператор подтвердил или изменил LLM-параметры при старте
- **THEN** содержимое workspace-файла `.env` остаётся прежним; выбранные LLM-значения действуют только на этот процесс бота

#### Scenario: Override побеждает значения из .env
- **WHEN** в `.env` заданы иные `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`, а скрипт запуска передал другие значения через окружение процесса
- **THEN** бот использует значения из окружения запуска, а не из `.env`

## MODIFIED Requirements

### Requirement: Связь с LLM на хосте
Когда выбран локальный LLM на хосте, бот внутри сандбокса SHALL обращаться к нему по адресу `host.docker.internal` (порт из конфигурации LLM). Параметры LLM (`LLM_BASE_URL`, и при наличии — модель и ключ) SHALL передаваться явными флагами окружения в команде запуска бота; значения тех же переменных из workspace-файла `.env` SHALL NOT перекрывать их. Разрешение сетевого доступа к хостовому порту LLM для локального сценария выдаётся разовой командой policy при подготовке.

#### Scenario: LLM доступна через прокси сандбокса
- **WHEN** бот запущен с override `LLM_BASE_URL=http://host.docker.internal:1234/v1` и политикой `localhost:1234` разрешена
- **THEN** запросы к LLM достигают сервера на хосте, агентный цикл получает ответы модели

#### Scenario: Явный override побеждает .env
- **WHEN** workspace-файл `.env` содержит `LLM_BASE_URL` со значением `http://localhost:1234/v1`, а запуск бота передаёт иной адрес через переменную окружения
- **THEN** бот использует адрес из переменной окружения, а не из `.env`

### Requirement: Runbook-скрипты жизненного цикла
Репозиторий SHALL содержать скрипт первичной подготовки сандбокса (создание сандбокса с workspace, установка python-окружения, editable-установка пакета) и скрипт запуска бота (поднятие остановленного сандбокса, интерактивный выбор параметров LLM, запуск процесса бота в фоне с override LLM и записью логов в VM-локальный файл). Оба сценария README SHALL описывать на уровне типовых операций (подготовка, ежедневный запуск с confirm LLM, обновление, пауза, полный сброс).

#### Scenario: Ежедневный запуск одной командой
- **WHEN** после перезагрузки хоста выполнен скрипт запуска и оператор принял дефолты LLM (Enter) либо ввёл свои значения
- **THEN** сандбокс поднят, процесс бота запущен в фоне с выбранными LLM-параметрами, бот отвечает в Telegram

#### Scenario: Логи наблюдаемы
- **WHEN** бот запущен скриптом запуска
- **THEN** журнал бота доступен внутри сандбокса в предсказуемом файле и читается командой просмотра хвоста файла

#### Scenario: Автозапуск отсутствует
- **WHEN** хост перезагружен и скрипт запуска не выполнялся
- **THEN** бот не работает; самовосстановление не производится (ручная модель восстановления)

#### Scenario: Полный сброс
- **WHEN** сандбокс удалён командой teardown и создан заново скриптом подготовки
- **THEN** персистентное состояние агента (файлы `/work`), установленные пакеты и образы начинаются с чистого листа

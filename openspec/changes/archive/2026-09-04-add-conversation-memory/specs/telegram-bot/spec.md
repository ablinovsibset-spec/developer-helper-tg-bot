# telegram-bot Delta

## MODIFIED Requirements

### Requirement: Один длинный контекст на чат
Бот SHALL накапливать историю диалога отдельно для каждого чата и передавать всю историю в каждый запрос к LLM: сообщения пользователя, ходы ассистента (включая вызовы инструментов) и результаты инструментов. Reasoning-поле модели MUST NOT сохраняться в истории. История хранится персистентно в хранилище переписки (см. capability `conversation-memory`): сообщения пользователя и финальные ответы ассистента переживают перезапуск бота; инструментальный транскрипт присутствует в контексте только в пределах жизни процесса и после рестарта не восстанавливается.

#### Scenario: Контекст между сообщениями
- **WHEN** пользователь отправляет сообщение A, получает ответ, затем отправляет сообщение B
- **THEN** запрос к LLM для сообщения B содержит историю: A, ответ на A и сообщение B

#### Scenario: Инструментный транскрипт в истории
- **WHEN** при обработке сообщения выполнялись инструменты
- **THEN** последующие запросы к LLM содержат ходы ассистента с вызовами инструментов и tool-сообщения с их результатами

#### Scenario: Reasoning не попадает в историю
- **WHEN** модель вернула ответ с непустым reasoning-полем
- **THEN** это поле не сохраняется в истории и не передаётся в последующих запросах

#### Scenario: Рестарт бота не обнуляет контекст
- **WHEN** процесс бота перезапущен, после чего пользователь отправляет новое сообщение в чате с открытой сессией
- **THEN** запрос к LLM содержит переписку открытой сессии, восстановленную из хранилища, включая новое сообщение

### Requirement: Команда /new — новый чат
Бот SHALL обрабатывать команду `/new` как закрытие текущей сессии чата и начало новой и отвечать коротким подтверждением. После `/new` следующий запрос к LLM содержит только системный промпт и новое сообщение пользователя. Прошлые сессии SHALL сохраняться в хранилище и оставаться доступными для поиска по прошлым беседам. Команда `/new` MUST обрабатываться отдельным обработчиком команды, а не попадать в агентный цикл как обычный текст; сама команда MUST NOT добавляться в историю.

#### Scenario: Сброс контекста
- **WHEN** пользователь после диалога отправляет `/new`, а затем новое сообщение
- **THEN** запрос к LLM содержит только новое сообщение без предшествующей истории, а бот подтвердил начало нового диалога

#### Scenario: Прошлое доступно поиску после сброса
- **WHEN** сессия закрыта командой `/new` и пользователь спрашивает об итогах прошлой беседы
- **THEN** модель может найти переписку закрытой сессии инструментом поиска по прошлым беседам

#### Scenario: Команда не проходит агентный цикл
- **WHEN** пользователь отправляет `/new`
- **THEN** выполняется закрытие сессии и отправка подтверждения; вызов LLM и инструментов не происходит

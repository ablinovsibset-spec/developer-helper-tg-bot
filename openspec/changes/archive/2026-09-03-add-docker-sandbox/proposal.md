# Proposal: add-docker-sandbox

## Why

Инструмент `exec` выполняет команды, порождаемые LLM, напрямую на хосте через `asyncio.create_subprocess_shell` — с полными правами пользователя и доступом ко всей файловой системе. Для автономного агента это неприемлемый уровень доверия: одна кривая команда (или удачная «галлюцинация» модели) стоит испорченного хоста. Мотивация — защита хоста, не деплой и не воспроизводимость окружения.

## What Changes

- Команды инструмента `exec` исполняются в изолированном Docker-контейнере вместо shell хоста.
- Песочница живёт один агентный цикл (одно сообщение пользователя, до 8 шагов): создаётся при старте цикла, принудительно удаляется после финального ответа. Файлы переживают шаги внутри одного сообщения, но не сообщения.
- Docker становится жёстким требованием запуска: без демона бот не стартует (fail fast). Небезопасный host-режим не существует ни как конфигурация, ни как код-ветка.
- При старте: проверка `docker info`, уборка осиротевших песочниц по label, сборка образа при отсутствии.
- Контейнер запускается с ограничениями: `--memory 512m --pids-limit 256 --cap-drop ALL -u 1000`, сеть bridge с исходящим интернетом (нужна скиллам wttr.in/habr), без маунтов хостовой ФС.
- Системный промпт сообщает модели, что команды выполняются в Alpine-контейнере с временем жизни файлов до конца обработки сообщения.
- Вызов Docker — через CLI (`docker` binary), без новых Python-зависимостей.

## Capabilities

### New Capabilities

- `docker-sandbox`: жизненный цикл песочницы (контейнер на агентный цикл, уборка, самовосстановление), ограничения контейнера, валидация окружения при старте бота, требования к образу.

### Modified Capabilities

- `exec-tool`: команда исполняется в изолированном контейнере, а не в shell системы; появляется наблюдаемое поведение — файловое состояние живёт в пределах одного сообщения. Контракт «команда → stdout/stderr/exit_code/таймаут/обрезка» не меняется.
- `test-suite`: exec-тесты разделяются — поведение через шов-двойник остаётся в hermetic-наборе, реальные Docker-сценарии выносятся в опциональные тесты с маркером; дефолтный `pytest` обязан проходить без Docker.

## Impact

- **Код**: `src/dev_helper_bot/tools.py` (exec через `docker exec`), `src/dev_helper_bot/agent.py` (lifecycle-хук песочницы в `run_agent`), `src/dev_helper_bot/main.py` (startup-последовательность), новый модуль песочницы и `Dockerfile` образа в репозитории.
- **Зависимости**: новых Python-пакетов нет (docker CLI через существующий async-subprocess паттерн); системное требование — установленный и запущенный Docker.
- **Тесты**: `tests/unit/test_tools.py` — сплит unit/integration; новый маркер pytest для Docker-зависимых тестов; конфигурация pytest в `pyproject.toml`.
- **Документация**: README (требование Docker, запуск, остаточные риски), `.env.example` при появлении настроек песочницы.
- **Наблюдаемые изменения для модели**: ОС команд — Linux Alpine вместо macOS; `cd`/env между вызовами по-прежнему не сохраняются.

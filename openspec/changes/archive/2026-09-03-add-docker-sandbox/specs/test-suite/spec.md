# test-suite Delta

## MODIFIED Requirements

### Requirement: Изоляция тестов от внешних сервисов
Тестовый набор SHALL выполняться без реального доступа к Telegram API, LLM-серверу и Docker. Взаимодействия с Telegram, LLM и исполнителем команд песочницы SHALL имитироваться тестовыми двойниками (fake-объекты, локальный фейковый HTTP-сервер на localhost, двойник исполнителя команд). Тесты дефолтного набора MUST NOT требовать сетевого доступа за пределы localhost, MUST NOT читать реальные секреты из окружения разработчика и MUST NOT требовать установленного Docker.

#### Scenario: Запуск без внешних сервисов
- **WHEN** выполняется `pytest` на машине без запущенного LLM-сервера, без доступа к Telegram API и без установленного Docker
- **THEN** все тесты дефолтного набора проходят; ни один тест не падает из-за недоступности внешних сервисов

#### Scenario: Независимость от секретов разработчика
- **WHEN** переменные окружения `TELEGRAM_BOT_TOKEN` и `LLM_*` не заданы в процессе тестирования
- **THEN** набор тестов выполняется успешно без обращения к реальным токенам и ключам

### Requirement: Автоматическая проверка агентного поведения
Тестовый набор SHALL автоматически проверять сценарии спецификаций `agent-loop`, `exec-tool`, `skills` и `docker-sandbox`: агентный цикл по последовательности имитированных ходов модели (вызов инструмента → финал), накопление инструментного транскрипта в контексте, предел шагов с сообщением об остановке, возврат ошибок инструментов модели, загрузку скиллов в системный промпт. Поведение инструмента exec SHALL проверяться через тестовый двойник исполнителя команд (stdout/stderr/код выхода, обрезка длинного вывода с маркером, признак таймаута, сохранение и сброс файлового состояния). Реальные сценарии Docker-песочницы SHALL покрываться отдельным набором тестов с маркером `docker`, исключённым из дефолтного запуска.

#### Scenario: Проверка цикла с инструментом
- **WHEN** имитированный LLM сначала возвращает вызов инструмента, затем финальный текст
- **THEN** тест утверждает выполнение инструмента один раз, передачу его результата в следующий запрос к LLM и возврат финального текста в чат

#### Scenario: Проверка исчерпания шагов
- **WHEN** имитированный LLM на каждый ход возвращает вызов инструмента
- **THEN** тест утверждает остановку цикла после 8 вызовов LLM и отправку сообщения об остановке по лимиту

#### Scenario: Проверка поведения exec
- **WHEN** тестируется инструмент exec через двойник исполнителя команд (успешный вывод, ненулевой код выхода, длинный вывод, таймаут, доступность файла между шагами)
- **THEN** тест утверждает соответствие результата: stdout/stderr/код выхода, обрезка длинного вывода с маркером, признак таймаута, видимость файла в пределах сообщения — без Docker и сетевого доступа

#### Scenario: Проверка загрузки скиллов
- **WHEN** тестовый набор каталога скиллов содержит `.md`-файлы
- **THEN** тест утверждает, что системный промпт запроса к LLM содержит имена и содержимое всех файлов скиллов

### Requirement: Запуск набора одной командой
Весь дефолтный тестовый набор SHALL запускаться командой `pytest` из корня репозитория и завершаться успешно без ручной подготовки окружения, включая машины без Docker. Docker-зависимые тесты песочницы SHALL запускаться явно командой вида `pytest -m docker` и требуют установленного и запущенного Docker.

#### Scenario: Полный прогон
- **WHEN** в корне репозитория выполняется `pytest` на машине без Docker
- **THEN** pytest обнаруживает все тесты дефолтного набора, не выполняет docker-маркированные тесты и завершается с нулевым кодом выхода

#### Scenario: Явный запуск Docker-тестов
- **WHEN** выполняется `pytest -m docker` на машине с запущенным Docker
- **THEN** выполняются интеграционные тесты песочницы (создание, исполнение, таймаут, уборка, самовосстановление) против реального Docker

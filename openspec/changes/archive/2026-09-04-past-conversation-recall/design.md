# Design: past-conversation-recall

## Context

Мотивация — в proposal.md (Why). Текущее состояние: `MemoryStore` (memory.py) хранит сессии и user/assistant-сообщения, `search_history` — единственный инструмент доступа к прошлому; шов `HistorySearcher` привязан к `chat_id`; базовый системный промпт собирается в `build_system_prompt` (skills.py) из констант `REASONING_EFFORT_LINE`, `datetime_line`, `SANDBOX_ENV_LINE` и секций скиллов; агентный цикл `run_agent` (agent.py) исполняет инструменты молча, без логирования. Диагностика инцидента: данные в БД есть, инструмент работает при явном указании — рвутся решение модели позвать инструмент и отсутствие у модели «карты прошлого».

## Goals / Non-Goals

**Goals:**

- Дать модели двухшаговый путь к прошлому: обзор завершённых сессий (`list_sessions`) → точечный поиск (`search_history`).
- Гарантированное инструктирование модели о памяти независимо от загрузки каталога скиллов.
- Диагностируемость: каждый вызов инструмента видим в журнале.

**Non-Goals:**

- Семантический/векторный поиск, регистронезависимый LIKE для кириллицы, автозакрытие сессий при рестарте, команда `/history` (см. proposal — non-goals).
- Изменение схемы БД: существующих таблиц `sessions`/`messages` достаточно.
- Принуждение модели к вызову через `tool_choice`: цикл остаётся автономным, решение за моделью.

## Decisions

### D1. Формат обзора `list_sessions`
Обзор = последние по времени `LIST_SESSIONS_LIMIT = 10` завершённых сессий чата; для каждой — дата начала, число сообщений и превью первого user-сообщения сессии, обрезанное до `PREVIEW_CHARS = 120` символов с маркером обрезки. Открытая сессия не попадает в обзор. Пустой результат — явный маркер «Завершённых бесед в этом чате нет».

*Альтернативы:* превью из финального assistant-ответа (итог беседы информативнее начала, но финал часто длинный сводный текст, а начало стабильнее называет тему); показ `ended_at` (ничего не даёт модели — даты начала достаточно). Число сообщений оставляем: дешёвый сигнал масштаба беседы.

### D2. Один шов, расширенный методом
Протокол `HistorySearcher` (tools.py) расширяется асинхронным методом `list_sessions() -> str`; продакшн-реализация `ChatHistorySearcher` (memory.py) delegирует в новый метод `MemoryStore.list_completed_sessions(chat_id)`. Диспетчеризация `list_sessions` — в `execute_tool_call` рядом с существующей веткой `search_history`; спецификация `LIST_TOOL_SPEC` без параметров.

*Альтернатива:* отдельный протокол `SessionLister` и второй DI-параметр — отвергнута: два шва на одно хранилище и один `chat_id` усложняют сигнатуры `run_agent`/`execute_tool_call` без выигрыша в тестировании (двойник всё равно один объект).

### D3. Строка о памяти — в базовом промпте, не в скилле
Новая константа `MEMORY_ENV_LINE` в skills.py, включается в `build_system_prompt` сразу после `SANDBOX_ENV_LINE`. Содержание: прошлые беседы хранятся; при ссылках пользователя на прошлое — сначала обзор завершённых сессий, затем поиск по ключевому слову; не отвечать «не помню», не проверив инструменты. Скилл `skills/search-history.md` обновляется под двухшаговый паттерн, но критичная инструкция живёт в базовом промпте.

*Почему не только скилл:* гипотеза C диагностики — бот, задеплоенный не из чекаута репо, грузит пустой `skills/`; строка уровня `SANDBOX_ENV_LINE` от этого не зависит. *Почему и скилл тоже:* расширенные правила (выбор ключевых слов, регистр LIKE, честность при пустом результате) слишком объёмны для базовой строки.

### D4. Логирование — в цикле `run_agent`, имя + исход
Единая точка — место формирования tool-результата в цикле `run_agent`: `log.info` с именем инструмента и исходом (успех / ошибка выполнения), для вызовов, отклонённых валидацией, — `log.warning` с причиной отклонения. Аргументы и содержимое результатов не логируются: имя + исход закрывают диагностический сценарий «звал / не звал», не раздувая журнал и не дублируя переписку.

*Альтернатива:* логировать в `execute_tool_call` — отвергнута: ветка не видна, когда валидация отклонила вызов до исполнителя, а именно этот случай диагностически важен.

### D5. SQL обзора — одним запросом
`MemoryStore.list_completed_sessions` выбирает последние N завершённых сессий чата и первым user-сообщением каждой через подзапрос по `MIN(messages.id)` в пределах сессии — без N+1 и без window functions. Обрезка превью и сборка текста — в Python рядом с `_excerpt`-хелперами.

## Risks / Trade-offs

- [20B-модель всё равно пропускает вызов на расплывчатых вопросах] → строка промпта (D3) усиливает триггер, но не гарантирует; следующий шаг вне scope — `reasoning: high` или более сильная модель.
- [Превью начала беседы не отражает тему, если диалог ушёл в сторону] → число сообщений и дата дают контекст; модель может уточнить через `search_history` по слову из превью.
- [Логи без аргументов не позволяют воспроизвести неудачный вызов дословно] → принято сознательно (объём/приватность); при необходимости позже добавим DEBUG-уровень для аргументов.

## Migration Plan

Изменений схемы БД нет; развёртывание — рестарт процесса бота, новые сессии и обзоры работают на существующих данных. Откат — возврат к предыдущему коммиту, данные в БД не затрагиваются.

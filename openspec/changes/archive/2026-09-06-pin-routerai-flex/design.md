# Design: pin-routerai-flex

## Context

Routerai обслуживает `openai/gpt-5.6-luna` пятью endpoint'ами с разными ценами
(₽/1M входных): `openai/flex` 11.26, `openai` 22.51 (+28.13 при записи кеша),
`amazon-bedrock` 24.76, `openai/priority` 45.02. Дефолтная балансировка
балансирует по правилу «стабильность → цена» и в наших прогонах мигрировала с
flex на base после сетевого флапа провайдера (2 прогона `llm_error`,
последующие 100% base — дороже и без кеш-чтений). Провайдерский биллинг
(`usage.cost`, ₽) уже сохраняется в `usage_raw`, но не выделен в телеметрии и
не используется отчётами. Экспериментальная база: метки `routerai` (19
прогонов, смешанный роутинг) и `routerai-flex` (7 прогонов, пин) в
`benchmark.db`.

## Goals / Non-Goals

**Goals:**

- Гарантировать дешёвый endpoint (flex) для конфигурации routerai, не меняя
  контракт LLMClient.
- Превращать временные сетевые сбои облачного поставщика в повтор, а не в
  упавший прогон.
- Давать отчётам фактическую стоимость провайдера, сохраняя прайс-оценку как
  явный fallback.

**Non-Goals:**

- Не строим экономику на кеш-попаданиях: допуск кеша OpenSI/OpenAI
  вероятностный (в наших замерах hit rate одного и того же префикса колебался
  от 0/8 до 77% за вызов), TTL — минуты. Кеш — бонус, а не план.
- Не меняем боевой дефолт поставщика (LM Studio в `.env` остаётся).
- Не моделируем конверсию валют и не пересчитываем историю: billed_cost
  хранится в единицах провайдера (₽) как есть.

## Decisions

### D1. Пин — @-синтаксис в строке модели, не provider-объект в теле

`LLM_MODEL='openai/gpt-5.6-luna@provider=openai/flex&allow_fallbacks=false'`
проходит через существующий `OpenAICompatibleClient` без изменений кода
(проверено прогоном харнесса: 17/17 вызовов на flex по биллингу). Альтернатива —
`provider`-объект в теле запроса — потребовала бы расширения контракта
`LLMClient.complete` и пары бот/харнесс. Жёсткий `allow_fallbacks=false`
выбран сознательно: мягкое предпочтение позволило бы роутеру тихо увести трафик
на дорогой base (наблюдалось 12:58 UTC), что и есть предотвращаемый отказ.
Цена жёсткости — 404 при полной недоступности flex — обрабатывается ретраями
(D2).

### D2. Ретраи сетевых сбоев — в OpenAICompatibleClient, вокруг POST

До 3 попыток суммарно (пауза 1с, затем 3с) на: обрыв ответа/соединения
(`aiohttp.ClientError`, включая `TransferEncodingError`), таймаут, HTTP 5xx и
404 (404 при жёстком пине означает «endpoint временно недоступен»).
Не ретраятся: HTTP 400/401/402/413 — постоянные ошибки запроса.
Повтор — новый POST целиком; частично прочитанный оборванный ответ
неиспользуем (routerai не списывает средства за неуспешные запросы).
Телеметрия (ObservingClient) меряет `complete()` как единый вызов: ретраи
видны как увеличенная latency, без дублей строк — наблюдение не должно
знать о транспортных попытках.

### D3. `billed_cost` — отдельная nullable-колонка llm_calls + агрегат runs

`ALTER TABLE llm_calls ADD COLUMN billed_cost REAL` (идемпотентная миграция по
паттерну `prompt_roles`), `runs.billed_cost = SUM(...) FROM llm_calls` в
`finish_run`. Семантика absence ≠ 0: null — провайдер поле не отдал (LM
Studio), 0.0 — честный ноль. Существующий `estimated_cost` не трогаем: это
оценка по прайсу для сопоставимости экспериментов, billed — факт.

### D4. Аудит Q5: фактическая стоимость первична, оценка — fallback

Если среди вызовов отбора есть хотя бы один не-null `billed_cost` — Q5
печатает сумму фактического биллинга (₽) как основную строку; прайс-оценки
(сырая/эффективная) печатаются следом с пометкой «оценка». Иначе — как сейчас
(оценка, пометка при отсутствии кеш-данных). Смешанных меток не бывает в
одном прогоне: поставщик один на конфигурацию.

## Risks / Trade-offs

- [flex подорожает/исчезнет] → пин — одна строка в `.env`/модели; экономика
  контролируется по `billed_cost` в каждом прогоне, дрейф цен виден сразу.
- [Жёсткий пин: flex недоступен дольше окна ретраев] → прогон падает
  осознанным `llm_error` (лучше, чем молчаливая переплата ×2 на base);
  осознанность зафиксирована этим решением.
- [Ретраи увеличивают worst-case latency сообщения] → максимум +4с пауз до
  первого ответа; для Telegram-бота приемлемо, успешность важнее скорости.
- [Надбавка за запись кеша на flex (+25% на непопавших вызовах)] → уже учтена
  в измеренных −47%; экономика считается по billed, а не по прогнозу hit rate.

## Migration Plan

1. Миграция БД идемпотентна (ALTER при отсутствии колонки), старые записи
   остаются null.
2. Конфигурация routerai-flex — только документация (`.env.example`,
   README): боевой `.env` (LM Studio) не меняется.
3. Откат: убрать `@...` из строки модели и/или откатить коммит; схема БД
   обратно-совместима (лишняя колонка не мешает).

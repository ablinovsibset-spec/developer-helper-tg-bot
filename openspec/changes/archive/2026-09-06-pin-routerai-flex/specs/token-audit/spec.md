# token-audit Delta

## MODIFIED Requirements

### Requirement: Эффективная стоимость с кэш-скидкой
Аудит SHALL выводить стоимость в два слоя. Основной — фактическая стоимость
поставщика: сумма начисленных стоимостей вызовов из телеметрии, когда
поставщик их отдаёт; она приводится в единицах поставщика (₽) как есть.
Справочный — оценки по прайсу: сырая (все входные токены по входному прайсу)
и эффективная (кэшированные токены по отдельному конфигурируемому прайсу со
значением ниже входного по умолчанию), с явной пометкой «оценка». При
отсутствии фактических стоимостей основной строкой становится сырая оценка.
При отсутствии данных о кэше эффективная оценка SHALL приравниваться к
сырой с явной пометкой, а не маскироваться. Сравнение «до/после» по
целевому снижению стоимости SHALL вестись по сырым входным токенам;
кэш-скидка и фактический биллинг приводятся справочно.

#### Scenario: Фактическая стоимость доступна
- **WHEN** LLM-вызовы в отфильтрованных прогонах содержат фактическую
  стоимость поставщика
- **THEN** вывод показывает её сумму как основную строку, оценки по прайсу —
  следом с пометкой «оценка»

#### Scenario: Есть данные о кэше
- **WHEN** LLM-вызовы в отфильтрованных прогонах содержат cached_tokens
- **THEN** вывод показывает сырую и эффективную стоимости с указанием доли
  кэшированных токенов

#### Scenario: Данных о кэше нет
- **WHEN** отфильтрованные LLM-вызовы не содержат cached_tokens
- **THEN** эффективная стоимость равна сырой, вывод содержит пометку об
  отсутствии кэш-данных

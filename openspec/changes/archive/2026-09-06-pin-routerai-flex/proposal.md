# Proposal: pin-routerai-flex

## Why

Прогон задания observability на коммерческой модели (routerai, `openai/gpt-5.6-luna`)
показал: провайдер балансирует каждый запрос между endpoint'ами (`openai`,
`openai/flex`, `openai/priority`, `azure`, `amazon-bedrock`), и дефолтный роутинг в
наших прогонах садил трафик на base-тир, который (а) дерёт надбавку +25% за запись
кеша — 28.13 ₽/1M против 22.51 ₽/1M — и (б) ни разу не отдал чтение кеша, тогда как
`openai/flex` вдвое дешевле по входу и выходу и читает префикс-кеш по ~10% своей
цены. Валидационный прогон харнесса с пином на flex (`@provider=openai/flex` в
строке модели, без изменения кода) дал **−47% фактического биллинга** на идентичной
структуре трафика и втрое-четыре раза меньшую латентность в том же окне. Плюс
выяснилось, что наша телеметрия считает стоимость по плоскому прайсу и не видит ни
реального биллинга провайдера (поле `usage.cost` уже приходит и сохраняется в
`usage_raw`), ни четырёхставочную модель цен с кеш-записью.

## What Changes

- Зафиксировать пин routerai на `openai/flex` для benchmark- и боевой конфигурации
  routerai: `@provider=openai/flex` в строке модели (конфигурация + документация,
  код клиента не меняется — @-синтаксис уже проходит насквозь).
- Устойчивость к флапу пина: сегодня два прогона упали в `llm_error` из-за
  оборванных ответов провайдера; добавить политику повтора сетевых сбоев вызова LLM
  (детали — design).
- Телеметрия: сохранять провайдерский `usage.cost` отдельной nullable-колонкой
  `billed_cost` в `llm_calls` (сейчас он есть только внутри `usage_raw` JSON).
- Отчёты аудита: считать фактическую стоимость по `billed_cost`, когда провайдер
  его отдаёт; плоский прайс — оценочный fallback для поставщиков без поля (LM
  Studio).
- Отчёт до/после экономики routerai в `task/` (документ).

## Capabilities

### New Capabilities

_(нет — все изменения касаются существующих возможностей)_

### Modified Capabilities

- `llm-provider`: новое требование — предпочтение endpoint'а (routing-пин) в строке
  модели передаётся поставщику без искажений; новое требование — временные сетевые
  сбои облачного поставщика ретраятся до поднятия `LLMUnavailable`.
- `agent-observability`: требование о хранении usage расширяется — провайдерский
  `billed_cost` фиксируется отдельным полем (absence ≠ 0, как у токенов).
- `token-audit`: требование о расчёте стоимости меняется — приоритет у фактического
  `billed_cost`; прайс-оценка остаётся fallback и явно маркируется.

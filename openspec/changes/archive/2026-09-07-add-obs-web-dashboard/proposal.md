# Proposal: add-obs-web-dashboard

## Why

Телеметрия уже пишется в SQLite, а CLI (`obs-dashboard.py`, `obs-audit.py`) даёт
сводку и аудит только по запросу из терминала. Во время ответа бота в чате нет
способа вживую видеть список прогонов, timeline выбранного run и агрегаты —
наблюдение отстаёт от самого агентного цикла.

## What Changes

- В том же процессе, что и long-polling бота, поднимается HTTP-дашборд на
  `127.0.0.1:8765` (простой HTML+CSS): сводка, список прогонов, timeline
  выбранного прогона, вкладка аудита (вопросы Части 2).
- Страница обновляет данные опросом раз в 1–2 с; текущий прогон выбирается
  вручную из списка (без автоследования).
- Фильтры `label` и `since` доступны на сводке и на аудите.
- `TelemetryStore` получает read-методы для агрегатов, списка/timeline прогонов
  и аудита — веб читает только через них.
- Если телеметрия не открылась, бот и веб стартуют, UI показывает
  «телеметрия недоступна». Если веб не смог занять порт — бот **не** стартует,
  в лог/stderr понятная причина.
- CLI-скрипты дашборда и аудита **не** удаляются и не меняют контракт.

## Capabilities

### New Capabilities

- `obs-web-dashboard`: in-process веб-UI телеметрии — сводка, список прогонов,
  timeline, вкладка аудита, poll 1–2 с, bind localhost, fail-fast при порте,
  заглушка при недоступной телеметрии.

### Modified Capabilities

- `agent-observability`: хранилище телеметрии расширяется read-API для сводки,
  реестра/timeline прогонов и данных аудита (веб и потенциально другие
  читатели); CLI-dashboard остаётся обязательным.

## Impact

- Код: `telemetry.py` (read-методы), новый модуль веб-UI (aiohttp), `main.py`
  (lifecycle HTTP рядом с polling), `config.py` (порт при необходимости),
  README / `.env.example`.
- Зависимости: новых нет (`aiohttp` уже в проекте).
- Поведение агентного цикла и запись телеметрии не меняются; CLI остаётся.
- Не входит: SSE/WebSocket, auth, LAN-доступ, React/SPA, замена CLI,
  публикация порта наружу из sbx без явной настройки хоста.

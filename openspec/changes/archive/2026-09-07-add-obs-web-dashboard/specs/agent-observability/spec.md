# agent-observability Specification (delta)

## ADDED Requirements

### Requirement: Чтение телеметрии через хранилище
Хранилище телеметрии SHALL предоставлять операции чтения для: агрегатов
прогонов (с фильтрами по метке и дате начала), списка прогонов, timeline
конкретного прогона (LLM-ходы и tool-вызовы в порядке хода) и данных,
достаточных для аудита потребления токенов (топ инструментов, распределение
по turn_number, разбивка prompt_roles, повторные токены, стоимости).
Отсутствие данных у поставщика (nullable-поля) SHALL сохраняться при чтении:
null не подменяется нулём. Сбой чтения MUST NOT прерывать запись телеметрии
и обработку сообщений бота.

#### Scenario: Агрегаты с фильтром
- **WHEN** читатель запрашивает агрегаты с меткой и/или since
- **THEN** возвращаются суммы и средние только по подходящим прогонам

#### Scenario: Timeline прогона
- **WHEN** читатель запрашивает timeline существующего run_id
- **THEN** возвращаются LLM-ходы и tool-вызовы этого прогона с токенами
  и длительностями

#### Scenario: Пустой результат
- **WHEN** фильтры не находят прогонов или run_id неизвестен
- **THEN** операция чтения завершается без исключения с пустым/отсутствующим
  результатом, пригодным для понятного UI-сообщения

#### Scenario: Nullable usage
- **WHEN** у вызова cached/reasoning-токены в БД равны null
- **THEN** чтение возвращает null, а не 0

## ADDED Requirements

### Requirement: Пошаговый прогресс индексации
Во время обработки поддерживаемого документа пользователь SHALL видеть прогресс по этапам: получение файла, извлечение текста, создание фрагментов, генерация эмбеддингов, готовность индекса. Статус MUST обновляться на одном сообщении в чате, а не отдельным сообщением на каждый шаг. Ошибка на любом этапе MUST оставлять в чате понятное сообщение и MUST NOT оставлять частичный индекс.

#### Scenario: Успешная индексация с шагами
- **WHEN** пользователь отправляет поддерживаемый документ в пределах лимитов
- **THEN** в чате одно статус-сообщение последовательно отражает извлечение текста, число созданных фрагментов, генерацию эмбеддингов и готовность документа к вопросам

#### Scenario: Прогресс эмбеддингов на большом документе
- **WHEN** документ даёт много фрагментов и эмбеддинги считаются не одним вызовом
- **THEN** статус показывает, какая доля фрагментов уже получила эмбеддинги, до сообщения о готовности

#### Scenario: Ошибка после показа прогресса
- **WHEN** извлечение, разбиение или эмбеддинги завершаются ошибкой после того, как статус уже показан
- **THEN** пользователь получает понятное сообщение об ошибке, и документ не появляется в индексе

### Requirement: Номера страниц PDF в источнике
Для PDF система SHALL сохранять для каждого фрагмента номер страницы или диапазон страниц, с которых взят текст. Результат поиска и указание источника в ответе агента MUST включать страницу, если она известна. Для `.txt`, `.md` и `.docx` страница отсутствует: источник — имя файла (и при наличии — номер фрагмента), без выдуманного номера страницы.

#### Scenario: Фрагмент с одной страницы PDF
- **WHEN** агент отвечает по фрагменту из `company_policy.pdf`, целиком лежащему на странице 17
- **THEN** источник содержит имя файла и страницу 17

#### Scenario: Фрагмент на стыке страниц
- **WHEN** фрагмент PDF пересекает границу страниц 16 и 17
- **THEN** источник указывает диапазон этих страниц

#### Scenario: Не-PDF без страницы
- **WHEN** ответ опирается на фрагмент из `.md` или `.txt`
- **THEN** источник содержит имя файла и не выдумывает номер страницы

### Requirement: Гибридный поиск по документам
Поиск по документам SHALL сочетать семантический (векторный) поиск и текстовый поиск по содержимому фрагментов. Результаты двух каналов MUST объединяться в общий ранжированный список. Оба канала MUST учитывать владельца документа: текстовый поиск без фильтра владельца запрещён.

#### Scenario: Точное совпадение добирает фрагмент
- **WHEN** вопрос содержит редкую формулировку или номер, который векторный поиск ставит ниже текстового
- **THEN** объединённый результат включает фрагмент, найденный текстовым поиском у этого пользователя

#### Scenario: Текстовый поиск изолирован по владельцу
- **WHEN** документ пользователя A лексически совпадает с запросом пользователя B
- **THEN** текстовый и объединённый поиск для B не возвращают фрагменты документа A

### Requirement: Reranking после первичного отбора
После объединения кандидатов из каналов поиска система SHALL выполнять отдельный этап переранжирования и только затем отдавать модели Top-K фрагментов. Кандидатный набор MUST быть шире финального Top-K. Переранжирование MUST NOT требовать отдельного вызова чат-модели.

#### Scenario: Финальный Top-K после rerank
- **WHEN** гибридный поиск набирает больше фрагментов, чем итоговый Top-K
- **THEN** инструмент возвращает не более Top-K фрагментов в порядке после переранжирования

#### Scenario: Rerank не зовёт чат-LLM
- **WHEN** выполняется `search_documents`
- **THEN** этап переранжирования не обращается к чат-completions

### Requirement: Conversation-aware retrieval
Поиск по документам SHALL учитывать предшествующие реплики открытой сессии чата, а не только строку `query` от модели. Анафорический follow-up MUST находить те же документы, что и полный вопрос с подставленным референтом. Контракт инструмента `search_documents(query)` MUST NOT требовать новых аргументов.

#### Scenario: Follow-up с местоимением
- **WHEN** пользователь спросил про дни отпуска, получил ответ, затем спрашивает «а можно перенести их на следующий год?» и модель вызывает поиск с этим коротким запросом
- **THEN** поиск возвращает фрагменты про перенос отпуска, а не пустой результат из-за неразрешённого «их»

#### Scenario: Первое сообщение без истории
- **WHEN** в открытой сессии ещё нет предыдущих реплик
- **THEN** поиск выполняется по `query` модели без выдуманного контекста

## MODIFIED Requirements

### Requirement: Инструмент search_documents
Агент SHALL иметь инструмент поиска по документам текущего пользователя. Retrieval MUST выполняться через этот инструмент по запросу модели, а не путём постоянной подстановки всех документов в system prompt. Результат инструмента SHALL содержать релевантные chunks, имена исходных файлов, индекс chunk и, если известна, страницу PDF. Отбор фрагментов MUST идти через гибридный поиск и rerank, с учётом истории сессии, как требуют соседние требования этой capability.

#### Scenario: Модель вызывает поиск
- **WHEN** пользователь спрашивает о содержании загруженных документов и модель вызывает `search_documents`
- **THEN** инструмент возвращает Top-K релевантных chunks только из документов этого пользователя

#### Scenario: Пустой результат поиска
- **WHEN** поиск не находит релевантных chunks
- **THEN** инструмент сообщает об отсутствии результатов, а ответ пользователю MUST NOT выдавать общие знания модели как факты из документа

#### Scenario: Результат с страницей PDF
- **WHEN** найденный фрагмент принадлежит PDF и для него известна страница
- **THEN** текст результата инструмента содержит имя файла и номер (или диапазон) страницы

### Requirement: Source attribution в ответах по документам
Когда ответ опирается на найденные chunks, финальный ответ пользователю SHALL указывать источник: имя файла и, если известна, страницу PDF. Номер страницы MUST NOT указываться, если его нет в результате поиска.

#### Scenario: Ответ со ссылкой на файл
- **WHEN** агент отвечает на вопрос на основе chunks из `vacation_policy.pdf` без известной страницы
- **THEN** ответ содержит указание источника с именем `vacation_policy.pdf`

#### Scenario: Ответ со страницей PDF
- **WHEN** агент отвечает на вопрос на основе фрагмента `company_policy.pdf` со страницы 17
- **THEN** ответ содержит имя файла и страницу 17

### Requirement: Изоляция документов по владельцу
Поиск и команды управления документами MUST учитывать владельца документа (Telegram user id). Документы одного пользователя MUST NEVER использоваться при ответе другому пользователю. Это правило MUST действовать для векторного поиска, текстового поиска и их объединения.

#### Scenario: Чужой документ не находится
- **WHEN** пользователь A загрузил документ, а пользователь B задаёт вопрос, ответ на который есть только в документе A
- **THEN** поиск для B не возвращает chunks документа A

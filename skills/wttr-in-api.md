# Скилл: wttr.in API (Тип A — инструкция к API)

Правила работы с сервисом погоды wttr.in через инструмент `exec` (curl).

## Форматы запросов

Всегда используй флаги `-s` (тихий режим) и `--max-time 10` (ограничение времени):

- Самый компактный ответ (одна строка, «город: эмблема температура»):

  ```bash
  curl -s --max-time 10 "wttr.in/Минск?lang=ru&format=3"
  ```

- Компактная строка по своему шаблону (`%c` эмблема, `%t` температура,
  `%f` ощущается как, `%w` ветер, `%h` влажность):

  ```bash
  curl -s --max-time 10 "wttr.in/Минск?lang=ru&format=%c+%t+(ощущается+как+%f)"
  ```

- Полные данные (JSON для промежуточной обработки, не для показа пользователю):

  ```bash
  curl -s --max-time 10 "wttr.in/Минск?lang=ru&format=j1"
  ```

## Правила

1. Локализация: всегда добавляй `?lang=ru`, чтобы тексты были на русском.
2. Компактность: для ответа пользователю достаточно `format=3` или своего
   короткого шаблона; JSON (`format=j1`) запрашивай, только если нужны детали
   (прогноз по часам, ветер и т.п.).
3. Один запрос на вопрос: не запрашивай одно и то же город дважды подряд —
   используй уже полученный результат из контекста.
4. Ограничение частоты: между запросами к wttr.in держи паузу не менее 1
   секунды. При ответе HTTP 429/503 подожди 2–3 секунды и повтори один раз;
   при повторной ошибке сообщи пользователю, что сервис погоды перегружен.
5. Город бери из запроса пользователя; если не указан — уточни или используй
   Минск (город по умолчанию).
6. Пользователю показывай компактный человекочитаемый вывод, а не сырой JSON.

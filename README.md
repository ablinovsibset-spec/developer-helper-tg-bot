# developer-helper-tg-bot

Telegram-бот — минимальный автономный агент: пересылает сообщения пользователя локальной LLM, модель может выполнять консольные команды через инструмент `exec`, следует текстовым скиллам и ведёт диалог в рамках одного длинного контекста на чат.

## Возможности

- **Агентный цикл**: модель вызывает инструмент `exec` (консольные команды), получает результаты и продолжает рассуждение до финального ответа (не более 8 шагов LLM на одно сообщение).
- **Скиллы**: каталог `skills/` — текстовые инструкции для агента (правила API wttr.in и утренняя рутина), автоматически встраиваются в системный промпт при старте.
- **Память диалога**: история каждого чата (включая инструментный транскрипт) хранится в памяти процесса и передаётся в каждый запрос; команда `/new` сбрасывает контекст.
- **UX**: «⏳ Готовлю ответ…» на время цикла, финальный ответ отдельным сообщением, разбиение ответов длиннее 4096 символов.

## Требования

- Python 3.11+
- Запущенный LLM-сервер с OpenAI-совместимым API:
  - [LM Studio](https://lmstudio.ai/) (по умолчанию `http://localhost:1234/v1`) с загруженной моделью `openai/gpt-oss-20b` (нужна поддержка tool-calling), или
  - [Ollama](https://ollama.com/) (`http://localhost:11434/v1`), или
  - любой облачный провайдер (OpenAI, vLLM и т.п.)

## Установка

```bash
git clone <url-репозитория>
cd developer-helper-tg-bot

python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate

pip install -e .               # вариант 1: editable-установка (рекомендуется)
# или
pip install -r requirements.txt  # вариант 2: только зависимости
```

## Настройка

1. Скопируйте `.env.example` в `.env`:

   ```bash
   cp .env.example .env
   ```

2. Заполните `TELEGRAM_BOT_TOKEN` — токен из [@BotFather](https://t.me/BotFather).
3. При необходимости скорректируйте параметры LLM:

   | Переменная | По умолчанию | Описание |
   |---|---|---|
   | `LLM_PROVIDER` | `openai_compatible` | Провайдер (LM Studio, Ollama /v1, vLLM, OpenAI) |
   | `LLM_BASE_URL` | `http://localhost:1234/v1` | Адрес OpenAI-совместимого endpoint'а |
   | `LLM_MODEL` | `openai/gpt-oss-20b` | Имя модели, обслуживаемой backend'ом |
   | `LLM_API_KEY` | — | Для облачных провайдеров; для локальных LM Studio / Ollama оставьте пустым |

## Запуск LLM-backend'а

Перед запуском бота поднимите локальный LLM-сервер:

- **LM Studio**: скачайте и загрузите модель `openai/gpt-oss-20b`, затем во вкладке *Developer* нажмите *Start Server* (порт `1234`). Модель должна поддерживать tool-calling — весь агентный режим построен на нативных вызовах инструментов.
- **Ollama**:

  ```bash
  brew install ollama        # macOS; или скачайте с ollama.com
  ollama pull <модель с tool-calling>
  ollama serve
  ```

  Тогда в `.env` укажите `LLM_BASE_URL=http://localhost:11434/v1` и имя модели.

## Запуск бота

```bash
# Через модуль
python -m dev_helper_bot.main

# Через console entry point (после pip install -e .)
dev-helper-bot
```

Бот работает через long-polling — публичный адрес и SSL не нужны. Найдите своего бота в Telegram и отправьте ему сообщение.

## Агентный режим

- Каждое сообщение пользователя запускает агентный цикл: модель может выполнять консольные команды инструментом `exec` (таймаут 30с, вывод обрезается до ~3000 символов) — бот выполняет их на вашей машине.
- История диалога накапливается в памяти процесса; перезапуск бота начинает новые пустые контексты.
- Команда `/new` сбрасывает контекст чата и начинает новый диалог.
- На время цикла бот отправляет «⏳ Готовлю ответ…»; если за 8 шагов финальный ответ не получен — приходит сообщение об остановке по лимиту.

## Скиллы

Скиллы — markdown-файлы в каталоге `skills/` в корне репозитория; имя файла без расширения — имя скилла. Все `.md`-файлы загружаются при старте и встраиваются в системный промпт (редактируются без переустановки пакета). Отсутствие или пустота каталога допустимы — бот стартует без скиллов.

В репозитории три скилла:

- `skills/wttr-in-api.md` (Тип A — инструкция к API): форматы запросов wttr.in через curl, компактный вывод, `?lang=ru`, ограничение частоты.
- `skills/habr-feed.md` (Тип A — инструкция к API): правила RSS-ленты Habr — верифицированная команда `curl | python3` для топ-статей за последние 24 часа, срез до 10 статей, чистка UTM-хвостов, HTML-ссылки в ответе.
- `skills/morning.md` (Тип B — рутина): утренняя сводка — погода в Минске (по правилам `wttr-in-api`) → топ-статьи Habr за сутки (по правилам `habr-feed`) → итоговая сводка до 4000 символов.

## Структура проекта

```
src/dev_helper_bot/   исходный код пакета
  main.py             точка входа/фасад бота (память чатов, /new, ⏳)
  agent.py            агентный цикл (лимит 8 шагов LLM)
  tools.py            инструмент exec (subprocess, таймаут, обрезка вывода)
  skills.py           загрузка skills/*.md в системный промпт
  config.py           настройки и фабрика LLM
  llm/                подпакет доступа к LLM (контракт с tool-calling)
skills/               текстовые скиллы агента (данные, не код)
tests/                тесты (unit/, integration/)
scripts/              служебные скрипты
pyproject.toml        главный файл конфигурации проекта
```
